# A 类语料生成契约（SPEC）

> **你是生成侧 subagent。只许读本文件，不许读仓库其它文件、不许联网。**
> 你的产出是**候选语料**（未验证），落盘为 JSONL，每行一个 JSON 对象。

## 0. 你要做什么

生成「**中国铁路车迷的真实问法/说法 → 系统应有的内部理解**」的评测回归语料。

- 输入：本文件给出的语义口径 + 站名/线路名白名单
- 输出：你那个批次的 `.jsonl` 文件
- 只回一行：`<批次名> <条数>`。**不要**输出语料正文、不要解释、不要总结。

## 1. ★ 最重要的契约（读三遍）

**你写的是「语义上正确的期望值」，不是「猜现在的代码会输出什么」。**

- 不许为了"让代码能命中"而削足适履、刻意选用例词。
- 你按中文语义判断「这句话**应该**被理解成什么」，照实写。
- 如果代码做不到，那正是语料的价值——校验器会把它标成 **GAP**，由人来决定补规则还是记缺口。
- 你的 KPI 是**语料的覆盖度与正确性**，不是"通过率"。

## 2. 输出格式

### 2.1 `intent_*` 批次（问法 → 意图/性质/槽位/路由）

每行：

```json
{"id":"emu_routing-0001","message":"G1今天由哪组动车组担当？","history":null,
 "expect":{"intent":"emu_routing","question_type":"realtime","slots":{"target":"G1"},
           "route":"fastpath","defer_reason":null},
 "note":"车迷核心问法","source":"gen:intent_schedule_routing"}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✔ | `<批次主题>-<四位序号>`，批次内唯一、稳定 |
| `message` | ✔ | 用户原话。**一句一个问题**，不要拼接多问 |
| `history` | ✔ | `null`，或 `[{"role":"user","content":"…"},{"role":"assistant","content":"…"}]` |
| `expect.intent` | ✔ | 8 选 1，见 §3.1 |
| `expect.question_type` | ✔ | `realtime` / `knowledge` / `mixed`，见 §3.2 |
| `expect.slots` | ✔ | 只写**关键**槽位 1–2 个；没有就写 `{}`。键见 §3.3 |
| `expect.route` | ✔ | `fastpath` / `llm` / `either`，见 §3.4 |
| `expect.defer_reason` | ✖ | 仅 `route=llm` 时可选，见 §3.5 |
| `note` | ✔ | 一句话：这条在测什么、为什么这样标 |
| `source` | ✔ | 固定写 `gen:<你的批次名>` |

### 2.2 `phrasings_*` 批次（说法 → 内部值）

每行：

```json
{"id":"time-0001","table":"time","raw":"十月一日",
 "expect":{"kind":"date_md","month":10,"day":1},"note":"用户实测缺陷","source":"gen:phrasings_time_window"}
```

| 字段 | 说明 |
|---|---|
| `table` | `time` / `window` / `seat` / `type`，决定被测函数（见 §4） |
| `raw` | 用户原话片段（**不含上下文**，解析器只看这一段） |
| `expect.kind` + 参数 | 见 §4.2 |

## 3. `intent_*` 语义口径

### 3.1 intent（8 选 1）

| 值 | 含义 | 典型问法 |
|---|---|---|
| `photo_spot` | 拍摄点/机位 | 「南京站哪儿拍车好」「XX 机位怎么走」 |
| `schedule` | 列车时刻/经停/历时 | 「G1 几点开」「G1 经停哪些站」「全程几个小时」 |
| `emu_routing` | 动车组交路/担当 | 「G1 由哪组担当」「这车底跑哪些交路」「CR400AF-5054 跑哪趟」 |
| `rail_line` | 线路/径路/里程 | 「京沪高速线多少公里」「北京到上海走哪条线」「京沪线沿线车站」 |
| `station` | 车站/站点信息 | 「北京南有几个站台」「XX 站电报码」「XX 站在哪个城市」 |
| `ticket` | 余票/票价/席别 | 「还有票吗」「二等座多少钱」「候补」 |
| `news` | 铁路资讯/动态 | 「最近有什么新线开通」「调图消息」 |
| `general` | 其它/闲聊/无明确主诉求 | 「你好」「今天天气」 |

> ⚠️ 难点（正是要考的）：**「京沪线沿线有哪些车站」是 `rail_line` 不是 `station`**；
> 「G1 经停哪些站」是 `schedule` 不是 `station`；「G1 由哪组担当」是 `emu_routing` 不是 `schedule`。

### 3.2 question_type（3 选 1）

- `realtime` — 答案依赖数据源、随时间或具体对象变化：**时刻、余票、今日担当、开行状态、径路里程、当前配属**。
- `knowledge` — 答案相对稳定、不依赖实时数据：**车型技术参数（功率/编组/动力）、厂商品牌、发展历史、样车编号、命名规则、谱系对比**。
- `mixed` — 兼有实时与知识诉求（如「G1 今天开吗，用的什么车型，这车型什么牵引功率」）。

> ★ 红线：**径路里程属于 `realtime`**（要查数据），**车型参数属于 `knowledge`**（可用模型知识）。

### 3.3 slots（槽位）

只写**关键槽位**，1–2 个就够；宁缺毋滥。

| 键 | 内容 | **字面形式要求（必须一致）** |
|---|---|---|
| `target` | 车次 / 车型 / 线路名 | 车次**大写**（`G1`）；车型**大写**（`CR400AF`）；线路用**规范名**（`京沪高速线`） |
| `direction` | 区间方向 | **箭头形式**：`北京→上海`（不是「北京到上海」） |
| `time` | 时间 | **照原话**：`今天` / `明天` / `今天下午` / `14:30` |
| `location` | 站名 | **不带「站」字**：`北京南`（不是「北京南站」） |
| `extra` | 其余关键细节 | 一句话 |

### 3.4 route（路由判定）

- `fastpath` — 这条**应该**能被确定性规则接管（关键词+槽位都齐全，问法明确）。
- `llm` — 这条**应该**交回模型（知识型/开放型/无槽位/超长/闲聊）。
- `either` — 两者都可接受。**拿不准就诚实写 `either`，不要硬猜。**

目标比例：`fastpath ≥60%`、`llm ≥20%`、`either ≤20%`。

### 3.5 defer_reason（仅 `route=llm` 时可选）

**★ 重要：这是"规则为什么没接管"的机械原因，不是"这句话语义上是什么类型"。**
四者按**固定顺序**判定，先命中先返回：

1. 输入为空 或 **句子 > 120 字** → `EMPTY`
2. 命中知识型触发词表 → `KNOWLEDGE_OR_OPEN`
3. 命中了某个问法族、但**缺关键槽位** → `NO_SLOT`
4. 以上都不是（没匹配到任何已知问法族） → `UNKNOWN_FAMILY`

| 值 | 含义 |
|---|---|
| `EMPTY` | 输入为空 **或句子超过 120 字** |
| `KNOWLEDGE_OR_OPEN` | 命中知识型触发词表（`为什么`/`为何`/`区别`/`有什么不同`/`原理`/`历史`/`由来`/`命名`/`参数`/`功率`/`速度是多少`/`厂家`/`品牌`/`关系`/`介绍一下`/`科普`/`怎么样`） |
| `NO_SLOT` | 问法匹配到了，但**缺关键槽位**（无车次/站名/区间/车型/线路） |
| `UNKNOWN_FAMILY` | 没匹配到任何已知问法 |

> ⚠️ **最容易写错的地方**：很多知识型问题的说法里**并不含触发词**。
> 例：「复兴号这个名字是怎么来的？」**不含**触发词表里的任一词（注意「怎么来的」≠「为什么」），
> 代码路径上属于「没匹配到任何已知问法族」→ **`UNKNOWN_FAMILY`**。
> 而「明天南京天气怎么样？」**含**「怎么样」→ **`KNOWLEDGE_OR_OPEN`**。
> **照实按上表四步顺序推**，不要凭"这句话是不是知识型"直接下结论。
>
> ✔ 判断顺序自查：先看是否 >120 字 → 再看有没有触发词 → 再看有没有家族缺槽 → 否则 UNKNOWN_FAMILY。

### 3.6 硬门槛（决定 `route` 的关键）

- **句子 > 120 字** → 一律交回 LLM（`route=llm`）。
- 含以下词 → `KNOWLEDGE_OR_OPEN`：`为什么`、`为何`、`区别`、`有什么不同`、`原理`、`历史`、`由来`、`命名`、`参数`、`功率`、`速度是多少`、`厂家`、`品牌`、`关系`、`介绍一下`、`科普`、`怎么样`。

## 4. `phrasings_*`：表 → 函数 → 期望值

### 4.1 四张表

| `table` | 被测函数 | 测什么 |
|---|---|---|
| `time` | `app.dates.resolve_date` | 日期：中文数字日期、星期、节日、相对日期、非法日期 |
| `window` | `retrieve._parse_time_window` | 钟点与模糊时段（早上/上午/中午/下午/晚上） |
| `seat` | `retrieve._parse_seat` | 席别（一等座/二等座/商务座/硬卧/软卧…） |
| `type` | `retrieve._parse_train_type` | 车种（高铁/动车/普速/直达/特快…） |

### 4.2 `expect.kind` 取值（**必须严格用这些**）

| kind | 参数 | 含义 |
|---|---|---|
| `date_iso` | `value` | 明确日期，`"2026-10-01"` |
| `date_offset` | `days` | 相对今天的天数偏移（`0`=今天，`1`=明天，`-1`=昨天） |
| `date_md` | `month`,`day` | 月日；**已过去的日期顺延到明年** |
| `date_next_month` | `day` | 下月某日 |
| `date_weekday` | `weekday` | 星期几，`0`=周一；**最近一次含今天** |
| `date_none` | — | **应当不识别**（非法/不可判） |
| `value` | `value` | 字符串结果（window/seat/type 用） |
| `none` | — | 期望**空串** |
| `tuple` | `value:[a,b]` | 时段，`[起, 止]` |

**约定**：相对日期一律用 `date_offset`（不要写死 `date_iso`），否则语料会随时间腐坏。

### 4.2.1 seat / type 的 `value` 写**中文语义值**

`sit`/`type` 两张表，`expect.value` 一律写**中文的语义正确值**（如 `一等座`、`硬卧`、`高铁`、`普速`），
**不要**去猜内部的英文枚举码——校验器负责把中文映射成代码的实际返回。
这样写的好处：生成方只描述"用户说的是什么"，代码内部改名不影响语料。

参考：`seat` 合法语义值 `一等座 / 二等座 / 商务座 / 特等座 / 硬座 / 软座 / 硬卧 / 软卧 / 高级软卧 / 动卧 / 卧铺 / 无座`；
`type` 合法语义值 `高铁 / 动车 / 城际 / 直达 / 特快 / 快速 / 普速 / 普快`。
（`普快` 与 `绿皮车` 是绰号/泛称，代码目前可能归并到 `普速`——照实写你的语义判断，差异正是 GAP。）

### 4.2.2 window 的已知边界（照语义写，别迁就）

`_parse_time_window` 返回 `(起, 止)`，未识别为 `('','')`。你按**中文直觉**写区间即可
（「早上」写 `["06:00","09:00"]`）。若代码取的是别的边界，那正是要暴露的 GAP，
**不要**为了迎合而改你的直觉值。

### 4.3 「不认识」也是正确答案

非法/歧义样本（如 `二月三十`、`25点`、`第十三月`）**必须进表**，期望 `date_none` / `none`。
这是**钉住"宁可说不认识，不要瞎猜"**的红线用例，价值极高。

## 7. 车次与车型写法

- 车次：`G1`、`G1234`、`D301`、`Z5`、`T109`、`K1234`、`1461`。**大写**，不带「次」字进 `target`。
- 车种字母含义：`G` 高铁 / `D` 动车 / `C` 城际 / `Z` 直达 / `T` 特快 / `K` 快速 / 纯数字 普快。
- 车型：`CR400AF`、`CR400BF`、`CRH380A`、`CRH2A`、`CR200J`（复兴号动车组）。**大写**。
- 车组号：如 `CR400AF-5054`（**不要**自己改写格式）。

## 8. 质量要求

1. **去重**：`message` 不要重复；同一问法换不同站名/车次才算新条目。
2. **多样**：口语/书面/简称/错别字/带语气词都要有（车迷真实说话不规整）。
3. **单一意图**：一条只考一个点，不要把意图判定混在一起。
4. **`note` 有用**：说明「在测什么边界」，别写「测试用例」这种废话。
5. **JSON 合法**：每行一个完整 JSON 对象，**不要**包成数组，不要尾随逗号。
6. **UTF-8**，中文不转义。

## 9. 交付

写入指定路径（父目录已存在），UTF-8，每行一个 JSON 对象。

最后**只回一行**：`<批次名> <条数>`

例如：`intent_ticket 52`
