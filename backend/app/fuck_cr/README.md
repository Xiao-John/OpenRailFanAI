# FUCK_CR

> **China Railway Compatibility & Unsolicited Innovation Recovery Layer**
>
> *Making yesterday's perfectly valid assumptions work again, one breaking change at a time.*

字母升官，代码加班。

本补丁负责车次规则的版本隔离与迁移准备。它的诞生有赖于一个富有启发性的发现：同一个标识符可以保持拼写不变，同时宣布昨天的含义不再适用。

我们感谢国铁集团持续提供现实世界的回归测试题材。否则维护者可能误以为，软件维护只是软件本身的事情。

## 先把开关装上

当前阶段是开关与影子观察，**新版运行规则尚未完成**。

| `FUCK_CR_MODE` | 当前行为 |
| --- | --- |
| `legacy` | 默认。现行解析、筛选和服务分流保持原样。 |
| `shadow` | 仍执行现行规则；额外观察完整的新格式候选，累计新旧候选异。 |
| `reform_2026` | 新版入口已保留，但启动配置校验明确拒绝；等待完整适配及数据源验证。 |

在后端环境中设置 `FUCK_CR_MODE=shadow`，重启该后端即可进入观察模式。回退设置 `FUCK_CR_MODE=legacy` 并重启。Settings 有进程缓存，修改环境变量不会使已运行的服务热切换。

Main 已增加供“一键FUCK_CR”按钮预接的 `GET /api/fuck-cr/status` 与 `POST /api/fuck-cr/activation`。新版未就绪时开启请求明确返回409；接口不会写环境或热切换模式。详细契约见仓库 `docs/backend-fuck-cr-button-handoff-20261019.md`。按钮已经准备好加班，不代表业务规则已经批准上岗。

拼写错误会报错，不自动猜测。`reform_2026` 也不会悄悄退回旧版：如果要求的是新版，服务必须明确说明它还没有准备好。

发布日期不是开关。转述日期也不是开关。表达对改革的热情，同样不能代替开关。

## 影子观察做什么

目前接入 `service_dispatch.train_codes`，比较旧版返回的号码集合与未来格式候选。支持观察 X/V、DH/DJ、五位数字及不认识的字头；不认识的字头作为完整候选保留，观察器不把它截成另一车次。

2026-10-18 起，影子观察使用独立的 `parser.py`，不再把旧解析结果填进新结果来制造一致。新旧解析器并存，实际服务仍取旧版返回值。

```python
from app.fuck_cr.parser import parse

result = parse('X1次、V6001次、DH1次', version='reform_2026')
assert result.codes == ('X1', 'V6001', 'DH1')
```

`tokens` 保留每次出现的原文、字符位置、完整号码、字头、数字、后缀、候选域、状态及原因；`codes` 另做首次出现顺序的去重。`legacy` / `reform_2026` 是显式语法档案，不是自动生效的业务分类。新档案仍保留 L 等旧号码，并标记 `legacy_only`，不替历史数据办理强制退休。

未知字头和超长号码作为完整 token 保留；车型/车组号、日期、时刻、单位数字不产出车次。五位数字不一概划为路用，资料已列明的货运段作候选提示，其余保留未知。`Z264/265/266` 的数字尾链保留未决，不扩号、不认作新旧关联。全角 ASCII 归一化保持原文字符位置，重复出现的号码也保留独立位置。

**候选不是营业列车证明，也不是客运工具的入场券。** DH/DJ/B 以及五位数字仍须经过未来的业务域与供应商准入设计。本补丁不开放这些新查询。

公开性能指标中新增：

```text
rule_comparisons.fuck_cr.syntax.calls
rule_comparisons.fuck_cr.syntax.same
rule_comparisons.fuck_cr.syntax.different
```

每次号码解析算一次调用，不能当成用户请求数。只保存计数，不保存问题、号码、未知原文或密钥。日期与车型在观察前排除；计数是语法候选差异，不能证明语义正确率。T/K 的历史含义变化不会仅靠这个语法指标被发现。

LM 仍执行旧版，不启用影子观察。完整配置摘要已经参与现有缓存隔离，切换模式不会串用同一份配置键。

## 向后矛盾兼容

通常，兼容层处理旧格式与新格式。这里还要处理同一种格式对自己昨天的解释提出异议。

因此：

- 历史数据按其业务日期和来源解释，不接受追溯性的字母晋升。
- 新版分类和供应商能力分开核验；动车组类别不能自动证明交路接口已经支持。
- 新旧号关联必须有依据；字头替换不等于逐趟映射。
- 不同日期的运行实例分别保留，不以“去重”为由让一天的列车消失。
- 未来仍可能发生行政创新。我们为其保留版本边界，不为其预先编造答案。

现行解析器尚未被替换，T/K 分流也未重写。新解析器已避免上述截号问题；只有影子路径使用新结果，生产服务不能据此宣称错误截号已全面修复。

## 为什么叫 FUCK_CR

较长的名字是 `china_railway_unplanned_compatibility_adjustments_and_associated_technical_debt`。维护者采用较短的标识，以节约内存，并向直观命名致以力所能及的敬意。

技术债通常由开发者创造。本项目感谢外部行政创新拓宽了债务来源。

讽刺留在补丁说明中；结果卡片、错误信息和查询事实按正常产品口径交付。
