# 机位标注裁决口径 v3（试行，2026-10-08）

沿用 v1 字段形状与 v2 城市绑定规则，新增下列两项。本版仅用于独立标注批次，不改变生产展示协议、运行字典或前端枚举。

## 铁路遗存目标

`view_target` 新增 `railway_remains`：原文明示废弃或停用的铁路设施、铁轨及遗存。静态展示的车辆仍用 `static_rolling_stock`；地铁与国铁都在运营时仍用 `operating_railway`。只写“旧铁路”“车少”或“像废线”不足以判断铁路遗存，不能自动套用。

这个类别描述原文拍摄对象，必须保留原文时效，不宣称线路当前停运，也不推导可进入现场。运营状态的独立字段尚未引入；不从目标类别生成停运结论。

## 经复核的实体别名

`entity_raw` 始终保留原文名称，不改写为规范名称。允许 `resolved` 引用外置 `entity-aliases.json` 中的已审映射，但须同时满足：

1. 规范实体存在于本批冻结目录，类型、ID、规范名及目录版本一致。
2. 原名在 claim 的逐字证据中；映射表保存原名、规范名、类型、ID、目录版本、来源及审核状态。
3. 映射只适用于表中明确批准的 occurrence_id，其原文哈希与位置锚点同时构成作用范围。禁止自动把别名推广到其他文档或地区。
4. `review_status=reviewed_ok` 才能使用。没有目录实体不能靠别名表临时造 ID，也不允许“加线”“去铁路”等普遍后缀替换。

外部资料仅用于审核实体身份，不能混入 source_documents 的逐字证据。待补录的实体单独登记，不修改现有目录哈希。

本轮批准四平原帖的“京哈”→京哈线（line_34），深圳原帖的“平南铁路”→平南线（line_261）。其他语境不自动沿用。prompt 与新批校验器须同步采用本口径。
