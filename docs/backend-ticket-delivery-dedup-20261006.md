# 票价与余票单渠道交付：后端修复交接

日期：2026-10-06。依据[重复展示问题交接](backend-duplicate-ticket-results-handoff-20261006.md)。范围：Main后端；未修改客户端、版本、安装包或发布内容。

## 已实现

重复来自同一工具事实同时进入正文和结构化卡片。现在检索完成后、首次正文事件前，流式与块式都使用同一结构化投影和逐记录覆盖判定。具备合并卡片能力的客户端不再收到被卡片完整承接的票价表、余票表及其重复标题、来源和采样时刻。

- 按车次、日期、实际起讫站匹配，同时分别验证价格和余票单项的金额/席别、状态、错误、说明、来源、采样时刻及接口时刻。不按关键词或数组位置删除正文。
- 一份文字回执有任一记录未被覆盖时，保留该份回执。未知类型/版本、投影拒绝、缺失身份或未登记的澄清文字继续降级展示。
- 卡片完整包含单项失败信息时，可以仅由卡片交付错误；另一项成功事实保持可见。筛选条件、截断、集合展示范围作为简短补充保留。
- 内部 `direct_complete` 区分“结构化交付已完成，正文合法为空”和“需要模型生成”。完整卡片回复无需生成模型，不先流出重复文字再用 `replace` 清空。
- 原始检索数据、来源、用量、SSE和结果卡片字段不删除、不改口径；时刻与交路文字保持原有交付。LM不启用此策略。

## 前端接入：可选能力声明

`GET /api/sessions` 在支持本次策略的Main后端新增：

```json
{"supported_client_capabilities": ["ticket_fare_availability_v1"]}
```

上述仅为新增字段示意；原有会话能力字段仍保留。前端先确认服务器支持该能力，且自身能解析并展示合并契约，再在两种聊天请求中附加：

```json
{"client_capabilities": ["ticket_fare_availability_v1"]}
```

请求仍使用 `POST /api/chat` 与 `POST /api/chat/stream`。`client_capabilities` 可省略，默认为空列表；限制32项，每项非空且最长80字符，重复值去重，未知能力不启用本策略。不会进入供应商配置或模型提示。

未声明的旧客户端继续收到票价与余票文字回执；不能仅凭应用版本自动删除正文。服务端没有公布能力时，客户端不要假设已经支持。LM不公布此能力，传入声明也不改变其行为。

声明后，完整结构化回复允许 `answer` 为空或没有正文SSE事件，但仍会有正常 `done`、`answer_done: true` 与真实 `display_results`。客户端须保存和显示无正文的卡片结果，并让复制/分享使用卡片内容；不得把空正文标成加载失败或模型连接错误。

本修复只影响新请求。已经保存在设备上的重复历史不会自动重写，仍由客户端按真实覆盖关系处理。未知能力/未声明请求与旧历史不被重新解释。
