# 服务商预设优化与配置向导设计

2026-10-19 更新：多平台向导代码已接入，具体范围与验证限制见 `frontend-multi-provider-wizard-20261019.md`。下文保留最初设计阶段的状态与待核对记录。

日期：2026-10-14。Main Android。目标：用户无需搜索引擎、额外教程或填写技术参数即可从选择服务商完成接入。

状态：预设编辑界面及首批硅基流动向导已接入Main并通过Kotlin编译；其他服务商向导仍为设计方案。未做用户注册、充值或真实密钥连接实测；不宣称零搜索验收通过。本次不构建、不发布、不修改后端正在进行的工作。

## 一、现有预设的修改

读取后端既有目录作为地址、接口和默认模型的真源，不另造一套连接目录，不覆盖已保存的密钥、用户地址或模型。

- 服务商选择层补充中性介绍。仅当预设ID及实际接口域名匹配时，展示对应官方帮助；自定义或改过地址的配置不冒充官方账户。
- 默认编辑区展示密钥、当前模型摘要、获取密钥帮助、更换模型、连接并使用；接口地址、模型手填和方言移到高级设置。自定义入口自动展开高级设置。
- 模型为空时读取账户的可用对话模型。硅基流动优先选择目录中存在的 `deepseek-ai/DeepSeek-V4-Flash`；没有匹配时，单模型账户可直接选择，多模型账户弹出选择层，不随机选取未知价格的模型。
- 不覆盖已配置模型。预设模型不存在时由连接反馈和“更换模型”恢复；不会静默改用另一个付费模型。
- “连接并使用”真实验证成功后才保存、设为当前服务并返回对话。验证失败不改已持久化配置；保存失败留在设置并提示重试。
- “记住密钥”语义沿用既有实现：关闭时本次运行仍可用；打开时本机加密保存。
- Main预设目录不展示Ollama、LM Studio、vLLM；不删除任何已保存配置。

实现：`MainSettingsScreen.kt`、`ProviderPresetHelp.kt`。此次仅Kotlin编译与差异格式检查，交互尚未实测。

## 二、向导入口与卡片

新用户：设置中的“开始配置向导”；已有未完成进度显示“继续配置”。普通添加入口保留，适合已有密钥用户。对话因未配置被阻断时，同一入口进入向导，不另造配置流程。

独立弹层高于设置内容，采用现有白/深色卡面、蓝色主按钮、16–20dp圆角；参考宽390dp，保留页面边距。标题、步骤进度、正文和操作保持稳定，仅切换当前一步。

每张卡片只做一件事：说明本步目的，列1–3条操作，提供唯一主操作。需要打开官网时分别提供“打开官网”和“我已完成”动作，不能因点击官网或切回应用就判定任务完成。官方域名可见，登录、证件和支付均在真实官网或支付应用完成。

返回保留进度；“稍后继续”关闭弹层。大字体/小屏允许卡片正文滚动，操作区在安全区内，无系统状态栏、设备外壳或示意元素。控件触控范围不小于44dp。

## 三、步骤与分支

| 状态ID | 卡片 | 操作及离开条件 |
| --- | --- | --- |
| choose | 选择服务商 | 展示类型、账户入口、可选模型范围和配置特点；用户选择并确认；已有密钥可跳转paste。 |
| account | 注册或登录 | 直达开放平台登录；内联说明账户入口与完成标志，返回后用户明确确认；已有密钥跳过。 |
| activate | 认证或开通 | 按服务商配置：必须/按官网提示/无需。不得对所有服务商强制认证；也不提供误导性的强制步骤跳过。 |
| credit | 确认可用额度 | 先判断用户是否已有额度；有则跳过充值。无则直达普通API用量账户充值/计费入口；自主选择金额，确认到账；不默认引导签约自动充值。 |
| key | 创建密钥 | 直达普通API密钥管理；名称可复制RailFanAI；列创建、复制和返回动作及完成标志。 |
| paste | 粘贴并连接 | 保留实际密钥隐私；自动配置地址/方言和预设模型，允许更换；告知简短测试请求，点击后才验证。 |
| finish | 完成 | 展示实际服务商和模型；保存成功后才显示完成；回到此前的对话和草稿。 |

已有账户、已有额度、已有密钥各有捷径，不强迫从头走。某平台采用开通或后付费时，credit卡片按平台计费模式调整，不能照搬“充值”。普通API与聊天会员、Coding Plan的用途需依据该服务商官方说明区分，不一概认定互通或不互通。

服务商介绍不做“最便宜/永久免费/一定可用”等无依据承诺。价格、额度有效期、支付要求采用注明日期的官方信息；若不可靠，不硬编码金额、首次赠额或每次查询成本。可一键打开官方定价页，不让用户自己搜索。

## 四、第一次应覆盖的流程素材

可交互设计以硅基流动及DeepSeek为样例；不是另造两家预设或减少原有服务商。其余云端预设仍可使用普通编辑流程，正式向导上线前必须补齐各自步骤素材。

### 硅基流动

- 注册/登录：`https://cloud.siliconflow.cn/`。官方文档说明支持短信或邮箱登录。
- 认证：`https://cloud.siliconflow.cn/account/authentication`。官方文档说明未实名不能充值。
- 额度/充值：`https://cloud.siliconflow.cn/expensebill`。选择在线充值，用户选择金额与支付方式；手机可能跳转支付应用；返回官网确认到账。
- 创建密钥：`https://cloud.siliconflow.cn/account/ak`，新建后复制完整密钥。
- 模型候选：`deepseek-ai/DeepSeek-V4-Flash`，只在账户实际可用列表中选中；不可用时不继续使用失效候选。
- 文档与页面跳转目标已经核对；登录后的手机界面、按钮位置及支付完成回跳尚未实测，不能补造界面截图。

### DeepSeek

- 开放平台：`https://platform.deepseek.com/`，不引导到仅聊天用的页面。
- 待核对直达路径：`https://platform.deepseek.com/api_keys`、`https://platform.deepseek.com/top_up`。本次访问被403阻挡，不能声称登录后的实际路径及按钮核对通过。可交互原型仅展示待核对流程，不作为发布素材验收。
- 认证按实际账户提示分支，不能借其他平台流程强制认证。
- 付费API采用预充值，账户要求及当前价格以开放平台为准；不承诺固定充值金额或赠送额度。
- 模型使用用户已更新的后端预设，不另写旧模型名称。

### 其余预设的素材要求

百炼须核对地域、普通API密钥及开通计费；智谱须核对普通API账户与模型权限；OpenAI须核对API账户和地区/计费；Kimi须核对开放平台账户；OpenRouter须核对网关账户、模型及额度；Gemini须核对AI Studio/API密钥、地区和项目计费。每家都有官网直达、菜单名称、完成标志、常见卡点和费用解释后，才允许标记“完整向导可用”。

## 五、恢复与错误设计

- invalid_key：留在paste，保留输入；提供重新粘贴及密钥管理直达。
- insufficient_quota：回到credit，保留密钥与模型；充值返回后用户点击重新连接。不能自动证明充值完成。
- model_unavailable：弹出已授权对话模型列表，重新选择；不得归因密钥无效。
- service_not_enabled/region_mismatch：定位到activate并说明平台要求；地址与地域一起变更前用户确认。
- network/rate_limited：原步骤重试，不引导充值或重建密钥。
- persistence_failed：说明连接成功但未保存，留在当前步骤；不能提前退出。

打开外部页面再返回，不根据resume事件自动推进，不重新发送付费测试。请求期间禁用重复点击，取消或退出后忽略过期结果。

## 六、状态、配置和隐私

向导步骤的应用逻辑使用不引用Android.*的Kotlin状态机；Compose负责界面、浏览器与生命周期适配，为后续SwiftUI保留接入边界。

进度只持久化provider_id、step_id、手动确认记录、guide_version与时间。密钥继续由MainSettingsRepository管理，不进入向导进度、链接参数、日志或截图。选择“不记住”时不因为需要恢复向导而暗中落盘；进程退出后返回paste要求重新填写。

每个服务商的素材独立版本化：官方链接、注册/认证/计费规则、操作文字、已核对来源、verified_at、手机实测状态。模型目录继续由既有后端提供；引导文案与型号不混成唯一真源。素材失效时呈现明确说明和官方控制台入口，不虚构按钮路径。

更换服务商只重置该分支及未提交配置，不删除已有服务商密钥或原对话。最终真实验证成功并保存后才启用新服务商。

## 七、零搜索验收定义

每家服务商分别验收：一位未使用过模型API的用户只依靠向导、官网和支付应用完成注册、必要认证/开通、确认额度、创建密钥、粘贴及首次正常对话；没有打开搜索引擎、查额外教程、手填技术参数或向工作人员问路。

明确记录每步是否需外部帮助，不设未经实测的“几分钟完成”承诺。按账户已有额度/已有密钥分别验证捷径；支付/浏览器回跳、进程被系统回收、取消、失败重试、替换服务商、恢复旧草稿必须覆盖。

用户能区分“我说已经完成”“应用已验证连接”“配置已保存”三种证据，才能避免假完成。

预设优化与完整向导上线分开验收。本次没有执行注册、付款、真实密钥连接或UI交互测试，尚无正式验收对照图；未来按项目规则通过 `scripts/acceptance.sh` 生成。
