## 对资料中迁移建议的修正

1. **识别不等于客运可查询。** DH/B 是货运、DJ 是检测类，五位数字也可能属货运或路用。识别应保存完整号码和候选域，服务准入另行判断，不能统一放进票价/余票与十车客运批量入口。
2. **车型类别不等于 rail.re 覆盖。** 将 `is_emu_train_code` 扩为 X/G/T/K/D/C 不能证明交路数据源已支持新号。应拆开“类别解释”与“该供应商能力”，未验证时保留未知状态。
3. **不能只靠系统当前日期切换。** 应看乘车/业务日期、已确认的具体实施范围和权威记录。第一批、第二批及历史查询会并存；具体实施日期未确认时不自动触发切换。
4. **跨日期不是重复。** 同一列车在不同日期是不同服务实例，不能为了“双表达去重”将两天结果合成一条。新旧号关联用于解释，只有同一日期、同一区间、同一已核验服务实例的重复记录才可合并。
5. **机读资料暂不能成为生产唯一规则源。** JSON 的 `effective.confidence` 是 A，但其中精确时点的 note 又注明来自 C 级转述；JSON/CSV 还存在 G(350) 映射与正文“A/推断”标注不一致。需要逐字段记录来源与置信度，分开“窗口”和“确切生效时刻”。当前 `check.py` 通过仅证明其已有检查通过，未覆盖上述语义冲突。
6. **对外文案也要保持同一证据门槛。** CR-04 的可复用文案写“11 月 25 日起”，比其来源约束更确定。目前应使用已确认的月份窗口，不能把转述精确日期写成正式安排。

原资料本轮未改写；上述作为后端接入前的差异记录。

## 建议内部结构

按三层拆分，现阶段仅定义方向，不冻结为外部接口：

| 层 | 责任 | 不承担的判断 |
| --- | --- | --- |
| 号码识别 | 完整 token、字头、数字、原文跨度；最长字头匹配；未知字头不截成数字 | 是否营业、是否可售、是否有交路 |
| 类别解释 | 编排版本、业务域、业务日期、有效范围、证据与置信状态 | 仅靠字母换算具体新车次 |
| 数据源准入 | 12306/rail.re 等各自支持的业务域、日期、格式及实测状态 | 用产品类别代替接口能力 |

“K 字头”是字面号码筛选，“快速”“普速”“动车”是用户类别意图，二者应分开。类别词不能在迁移期继续无条件映射固定字母集；缺少日期或“旧特快/新 T”语境时，应保留歧义或澄清。

号码识别建议区分 `recognized_candidate`、`legacy_supported`、`future_candidate`、`unsupported_domain`、`unknown` 等内部状态。它们只是候选设计，不能据此新增客户端必须理解的状态码。格式可识别但数据源未验证时，不自动发请求，也不宣称车次存在。

## 身份、映射与缓存

- 每次查询保留用户原号、数据源实际返回号、查询日期及来源；只有取得明确关联证据才展示新旧对应关系，不能把字头级映射变成逐车次替换。
- 建议逐趟映射记录包括旧号、新号、适用日期区间、适用线路/区间、来源、发布/核验时间及关系类型；允许一对多、多对一和未决关系，不预设纯一一映射。
- 内部编号也不能被假设永久稳定。跨改图的身份关联需来源证据；同日分段换号与跨日期改号分开处理。
- 车次身份、交路和类别解释缓存应包含相应业务日期；类别规则或逐趟映射更新后，带规则/映射版本的派生缓存需失效。
- 新增共享售票行模块仍按配置、日期、区间、乘客用途和刷新标识隔离，不因新旧号看似关联而跨日期共享。执行票价继续绑定原始行内部编号、区间站序和请求乘车日。
- 本地车次目录、GTFS 和公布票价保留原快照日期与有效期，不把旧号数据批量改名成新号。公布票价缺少新号记录时如实缺失，不能借旧号直接填补。
- 十车限额、逐日期结果和失败项保持现行契约；关联新旧号不能丢掉用户明确查询的某个日期或某个号码的结果。

## 分阶段实施与启用门槛

| 阶段 | 内容 | 允许启用的条件 |
| --- | --- | --- |
| 预备：本轮 | 风险清单、现状探针、候选结构、待确认项 | 不启用新运行规则 |

优先级最高的实际修复候选是“未知字母号码被截成另一车次”，它也是现有解析缺陷。是否扩大候选格式和是否开放新业务域应分开交付，避免把尚未实施的体系顺带上线。

## 后续回归清单

- 识别：X/V/N、DH/DJ/B、五位数字；大小写、后缀和标点；最长字头匹配；未知 `AB123次` 不得抽出 `123`。
- 旧输入：G/D/C/Z/T/K/Y/L、纯数字旧车次、年/月/公里/车型/车组号排除，历史上下文与指代不退化。
- 新旧语义：同一 T/K 号码在旧时期、新时期、未定切换时期的解释分开；X 保留不等于已开行。
- 服务边界：DH/DJ/货运/路用不误发 12306 客运查询；产品类别未知或供应商能力未知不伪造无记录结论。
- 多车多日期：跨两批切换、多号同日、多日同号、同日分段换号；不得跨日去重或静默替换用户输入。
- 数据与取消：邻站、车次/区间不符、旧词典、执行价失败、余票刷新、取消、缓存隔离和回退。

这些是计划测试项，不是已经通过的改革验收。本轮仅执行现状探针和资料库既有一致性校验。

## 待确认与前端边界
