# 旧版软件更新下载延迟观测

日期：2026-10-07。发布 0.1.24 后进行单次软件更新接口下载检查，没有修改更新业务代码。

- GitHub latest 为正式 `v0.1.24`；APK 41,323,504 字节，GitHub 资产 digest 与本地 SHA-256 一致。
- 以旧版 0.1.19 参数检查更新成功，能识别版本并取得受支持的 arm64 安装包。
- 下载接口在返回给客户端前完整取得远端 APK 并校验。日志显示 GitHub 下载重定向正常、资产 HTTP 200；本机试验客户端等待首个响应 150 秒后超时，随后服务器临时文件仅接收约 4.8MB。此结果证明资产可访问，不能证明完整文件下载及客户端安装成功。
- 当前后端整体下载时限 600 秒；Android `UpdateClient` 读取响应时限 180 秒。公网接收持续缓慢且超过 180 秒时，客户端可能先超时，即使后端仍在下载。每块读取的 60 秒时限不能限制整个下载耗时。

本次测试未改变共享词典、会话或安装包。软件更新真实结果仍需用户旧版真机核对；若应用内等待超时，可从正式 Release 手动下载并覆盖安装。

后续建议：前后端联合设计软件更新下载进度与取消协议，区分远端接收、完整性校验及本地回传，并统一等待策略。旧客户端已安装的等待时限无法仅靠新 APK 修改，应保留手动下载入口；后端需关注客户端断线后仍占下载槽的问题。以上为改进建议，不纳入本次发布完成项。
