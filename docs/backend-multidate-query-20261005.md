# 多日期查询

日期：2026-10-05。已合入当前 Main 后端源码，未推送代码、重启共享服务或更新 Release/APK。

## 行为

时刻、余票、票价和车次交路支持共同日期列表。例如：

> 明天后天大后天北京南到上海虹桥 G1 次票价

按本次铁路业务日分别查询 2026-10-06、2026-10-07、2026-10-08；每项保留车次、日期、实际区间、来源及失败原因。日期按中国时区一次归一化并去重。

支持完整公历日期、相对日期、明确月份后的简写日期，以及含首尾的日期范围，例如“10月6日、7日、8日”“明天到大后天”“2026-10-31至2026-11-02”。简写跨月不能猜测；未知日期、反向范围、非法日及超限请求不查询。

每次最多 10 个不同车次、10 个不同日期，即最多 100 个车次日期组合。四种服务各自执行，沿用既有并发限制；取消请求会清理正在执行与排队的任务。

“G1明天、G2后天”“G1明天余票、后天票价”及日期间夹杂各自时段或席别的表述要求确认，不猜绑定、不展开错误组合。未来交路不查询，也不用历史记录代替。最近交路与指定多日期不能混用。

## 兼容

- 单日期结构化动作优先于正文；定向重试仍只查询动作指定的日期。
- 多日期时刻按日期拆为现有时刻卡片或批量结果，防止旧客户端把不同日期的失败一起按第一天重试。
- 票价保持现有正文回执格式，兼容 `backend-fare-card-handoff-20261005.md` 所述前端识别；未新增候选 `ticket_fare` 类型。
- 展示协议仍为版本 1。`dates` 与 `query_date` 仅用于内部调度和投影，不增加客户端请求字段或结果种类。
- Main 预取不会把多日期缩成一次单日请求；模型补槽后的实时/混合请求也不能静默丢掉日期。
- LM、普通知识简答提示、Android 和 WebUI 均未修改。
