# 票价与余票重复展示：后端修复建议

日期：2026-10-06。依据用户0.1.20真机截图及当前源码只读检查；本轮只提出建议，未修改业务源码、未运行测试或重新打包。

## 现象与原因

同一回复包含纯文字票价回执（客户端又将其解析成旧票价卡片）、文字余票表格，以及最后的新版票价与余票合并卡片。属于两条展示渠道重复交付，不代表上游重复查询。

当前 service_batch.py 同时为 fare/ticket 构造 direct_answer 和结构化原始记录；display_result.py 最后投影 ticket_fare。orchestrator.py 在存在 direct_answer 时关闭结构化正文缓冲，并在结果卡片最终交付之前流出回执。客户端Markdown照常渲染这些回执，随后再次渲染合并卡片。前端现有去重对合并回执采取保守保留，不能消除该重复。

## 建议修复位置

统一在检索完成、正文交付之前确定展示策略。让流式和块式共享同一投影与覆盖判定，避免分别维护去重规则。候选文件：pipeline/service_batch.py、pipeline/ticket_answer.py、pipeline/orchestrator.py、pipeline/generate.py；最终范围由后端实施者确定。

### 1. 明确客户端能力，兼容旧版

建议新增可选请求能力声明，例如 client_capabilities 中的 ticket_fare_availability_v1。字段属于候选协议，需要与客户端同步接入，不能当作已经存在。未声明时保留原有回执；已声明且结构化结果通过协议验证时采用单渠道展示。

不能无条件清空所有客户端正文。0.1.19只识别纯票价、不能展示余票新增字段；若直接抑制余票回执，会让旧客户端失去真实结果。LM保持原行为。能力版本同时用于历史回复展示策略，不能重新解释旧结果。

### 2. 基于记录覆盖去重，不用正文关键词删除

在已验证的结构化投影上，按 train_code/date/from_station/to_station 精确身份建立覆盖关系，同时区分票价与余票。只移除被卡片完整承接的那份工具回执；不按数组下标、车次单字段或顶层status推断覆盖。

- 完整合并卡片覆盖两份回执时，正文无需再重复价格表、余票表、车次标题、来源和采样时间。
- 只覆盖一项时，另一项未覆盖的回执必须保留。
- 单项失败如果卡片已经携带身份、单项状态、原始错误和说明，也可由卡片独立交付；否则保留错误正文。
- 未知结果类型、版本、格式异常或无法确认身份时，保留文字降级。
- 区间缺失澄清、筛选条件、截断/展示范围提示以及卡片未承接的说明继续保留；必要时输出为简短补充说明，而不是整份重复回执。
- 不删除或更改原始检索事实，不重新拼接不同日期、相似站名的票价与余票。

建议在内部回执形成时记录来源身份/服务归属，按记录移除展示片段，避免用正则猜测大段自然语言是否重复。

### 3. 空正文仍需确定性完成，不能误触发模型

当前 direct_answer 使用字符串是否为空决定直接交付。去重后正文可能合法为空，不能因此进入模型生成、重述事实、消耗额外Token或发出模型连接错误。

建议用独立内部交付状态表示“工具事实已由结构化结果完整交付”，与“没有直接回答，需要模型”区分。不改变既有done结构：空正文仍发送真实display_results、来源、usage等元数据。

### 4. 流式不先发重复正文再收回

在首次answer事件之前完成投影和覆盖判定。结构化专用回复可仅交付阶段事件及done；混合回复只流出未覆盖的补充文字。不要等done再发replace清空已经显示过的回执，这仍会造成闪现、页面跳动和看似重复弹出。

块式返回相同展示正文与display_results；两种路径保持事实、状态和用量一致。普通问答、时刻/交路及现有取消行为不受影响。

## 建议验收

- 用户截图同类查询在具备合并展示能力的客户端中仅出现一张合并卡片，无前置旧票价卡片或余票表。
- 多车次、多日期各按完整身份独立显示一张，不能串值或跨日合卡。
- 票价成功/余票失败及反向组合保留成功事实和单项原始错误。
- 候补、全部无票、未知余票与金额缺失仍准确展示，不将未知改成无票。
- 部分记录未被投影覆盖、未知协议、截断提示、筛选条件及区间澄清不丢失。
- 未声明新能力的旧客户端保留完整文字回执；LM不变。
- 全部事实走卡片时无生成模型调用；流式无重复answer闪现；块式与流式最终结果一致。
- 历史重开、复制及分享保持完整事实。旧历史正文如何去重需要客户端展示层单独处理，后端新回执修复不会自动改变设备上已经保存的内容。

## 前端后续配合

后端确定可选能力声明后，客户端再同步声明并接入；不能提前对未知后端静默假设支持。历史回复去重仍保留严格事实覆盖约束。本次交接不授权自动发布，下一版包含双方修改后再完成真机复核。
