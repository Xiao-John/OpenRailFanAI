# Main Android结构化票价接入

日期：2026-10-06。依据[后端票价契约](backend-ticket-fare-contract-20261006.md)。

## 已落实

- `ChatModels.kt`识别版本1的`ticket_fare`，分别保留车次、日期、实际区间、接口到发时刻、历时、席别金额、币种、来源、采样时间、状态、错误和说明。金额保留十进制字符串，不以缺失值代替0元。
- `FareCard.kt`沿用现有圆角、配色和回复区排布。成功展示金额；部分结果标注金额不完整并对缺失金额显示“未提供”；空结果显示无精确票价记录；失败显示票价错误。详情可展开查看采样时间和全部真实来源，不渲染为模型连接错误。
- 到发时间标为接口区间时刻，不代表实时运行。票价不代表余票；无票价记录不推断无票或停运。缺字段不从问题或邻近时刻卡片补齐。
- 正文仍原样持久化；只有结构化结果成功解析且车次、日期、区间、时刻、历时和每项席别金额都匹配时，才从显示正文与复制/分享正文中移除对应重复票价行。说明、未匹配行及无法识别格式保留；未知协议仍使用原始Markdown降级。
- `ChatUiState.kt`修正混合结果合并：时刻按车次和日期区分，批次按日期分组；票价、交路、错误及未知类型留在批次外，避免被仅渲染时刻的组件遗漏。

## 实际执行价接入

依据[实际执行价交接](backend-executed-fare-handoff-20261006.md)，优先读取 fare_basis：executed 标为“实际执行票价”，published 标为“公布参考票价”。缺字段时仅根据明确说明或旧 queryAllPublicPrice 来源识别；无法识别时显示“票价信息”，不将历史公布价解释为执行价。口径同步显示于卡片、详情及复制/分享内容。部分缺失金额另设提示，不覆盖价格口径。

## 票价卡片分区修订

- 标题旁使用浅蓝状态标签；乘车区间放入独立浅色区块。
- 日期、历时采用带统一图标的信息块；接口到发时刻独立标注出发/到达。
- 席别表保留蓝色金额、浅色表头，增加席别行分隔线。
- 说明进入蓝色信息区，失败原因进入浅红提示区；来源与查询详情单独折叠，展开后按标签/值展示日期、采样时刻和数据口径。
- 旧格式票价回执仍保留全部原文，但以背景区块区分描述与金额表，不猜测自由文本字段。
- 配色跟随现有深浅主题，保持回复区与时刻卡片的圆角及字体层级。
