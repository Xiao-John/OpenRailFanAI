# 新版词典合入交接

日期：2026-10-07。

新版 `backend/data/dict.db` 已纳入机位攻略库：810 篇文档、265 个收录范围、2562 条发现查询记录。文档与查询记录内容未改，只补入数据版本和结构版本。篇数不等于机位数量。

## 后端已完成

- 软件升级时，机位库与时刻库分别比较数据版本。即使时刻版本相同，也能补入较新的机位库。
- 较旧或未携带机位数据的安装包，不清空、不覆盖较新的本地机位库。旧库没有版本时，使用已有记录时间比较；时间无效时拒绝覆盖。
- 兼容没有机位表、缺少 `content_hash` 列的旧词典。新版完整快照按表替换，清理过的文档不会因合并再次出现。
- 合入在同一事务内完成；失败回滚。更新前保存 `dict.update-backup.db`。
- 建库新增、发现记录变更、去重及重扫删除都会更新机位数据版本。
- 独立 GTFS 更新保留机位、公布票价、线路详情与车站缓存。

机位元数据保存在 `meta`：`photo_spots_version` 为 UTC 数据修订时间，`photo_spots_schema_version` 当前为字符串 `"1"`。此次存量数据版本为 `2026-10-07T07:59:19+00:00`，沿用最后一条记录的时间，不表示重新采集。

## 前端接入

无需新增聊天卡片。下一次打包请携带完整 `backend/data/dict.db`，确认其中保留 `photo_spot_doc`、`photo_spot_seed` 和上述元数据。

沿用原软件更新约定：包内词典存放到独立路径，通过 `DICT_BUNDLED_DB_PATH` 交给后端启动合入；运行词典继续使用 `DICT_DB_PATH`。两者不能指向同一文件，也不能每次启动直接覆盖运行词典。打包含词典时使用现有 `includeDict` 选项。

`GET /api/updates/dictionary/local` 新增可选 `photo_spots` 字段：

```json
{
  "available": true,
  "version": "2026-10-07T07:59:19+00:00",
  "schema_version": "1",
  "documents": 810,
  "scopes": 265
}
```

原顶层 `version` 仍表示 GTFS 版本，不能当成整个词典的版本。旧客户端可以忽略新增字段。无机位表时该字段的 `available` 为 `false`；未建立词典时仍兼容原返回形式。

软件更新与词典更新继续分开。当前在线词典更新源只提供 GTFS，不下载机位攻略；机位库通过携带完整词典的软件更新分发。不要将“时刻词典已更新”显示成“机位库已更新”。
