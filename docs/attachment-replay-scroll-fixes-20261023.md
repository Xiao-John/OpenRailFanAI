# 0.1.33：思考折叠、消息跟随及附件重生成

## 变更

- 思考区以请求标识保存流式展开状态，不再受 busy 的强制展开影响；完成后按默认折叠偏好显示。
- 将“到底”判断与“接近底部”判断分开。自动跟随和回底按钮等待布局，逐视口滚至最后一项实际底部，确认后清除阅读状态；不再靠一次读取旧布局尺寸并无条件清标。
- 接近底部门槛扩大为120dp与视口12%中较大者，同时不超过视口25%；离底阅读仍保持位置。
- 导入图片/文件不再自动填入提问；已有草稿不覆盖，仅清掉用于打开导入器的命令。用户输入问题后发送。

## 附件存储与重生成契约

新增 `AttachmentStore.kt`，在应用私有 `filesDir/attachments-v1/<会话UUID>/` 保存附件与请求快照。附件以 SHA-256 定位，同会话重复内容复用，引用包含版本、文件名、MIME、大小及摘要，不保存任意外部路径。请求快照包含原提问、当时实际发送的文本历史、附件引用、图片输入模式和思考开关；不保存 API Key 或供应商凭据。

用户消息与成功、失败、停止的助手消息保存 `request_ref`。重新生成及对应错误卡重试按该回复的引用重建请求，不以同名问题猜测附件，不借用当前新导入的附件。仍使用当前服务商及密钥，记忆开关继续按当前隐私选择生效；不承诺模型输出确定性，也不在历史中固定旧版OCR实现。

引用草稿随会话落盘，进程重启后恢复。读取附件时检查会话边界、大小和摘要；丢失或损坏则在发出请求前明确报错。旧版本只有“用过附件”标志、没有原文件的历史不能凭空恢复，需用户重新导入。旧纯文本回复也不会借用当前附件草稿。

删除会话时先取消该会话的活动请求，重置聊天状态，再清除其附件目录。已有历史引用的文件不按临时缓存过期；启动时按引用检查清理，只有无引用且超过24小时的快照及附件才可回收。损坏的清单使文件回收保守跳过。会话裁剪后引用不再保留的快照可在后续清理中释放。应用禁止系统备份；清除应用数据或卸载会一并移除附件。

## 验证范围

Kotlin `:app:compileDebugKotlin`通过，静态差异检查通过。尚未运行自动测试、模拟器、真机、真实图片或真实模型重生成验收；不将编译视为操作体验验收。正式发布流程另核验签名、版本、离线词典、源码提交及GitHub资产摘要。
