# 票价与余票合并：后端交接

日期：2026-10-06。范围：Main 后端。Android、WebUI、版本和安装包未修改；本说明交给前端接入，不能作为客户端已完成的证明。

## 查询行为

- 指定车次、乘车日期和实际区间后，问票价或余票都联查实际执行票价与实时余票。明确同时问两项时，每个车次、日期、区间只安排一份票价查询和一份余票查询。
- 继续支持最多10个不同车次和10个不同日期；超过车次数限制时整批拒绝并要求减少。两个服务共用既有并发上限，取消请求时清理子任务。
- 未指定车次的区间余票检索，先取得余票列表，再为本次展示的最多10条精确车次记录补查票价。缺少实际区间、查询日期或有效车次身份时不猜测、不补查。展示数量和截断说明沿用原有余票文字回执。
- 默认票价为 `executed`，不以公布价代替接口失败。明确问公布参考价时，价格仍从词典读取，余票独立在线查询；词典没有金额就保留失败。两种价格口径混问仍要求澄清。
- 只问票价时自动联查的余票不套用隐含席别/时段过滤，可以显示“无”；显式余票查询保留原来的筛选条件。没有符合条件的记录不等于列车停运，也不等于所有席别无票。

## 展示契约

保持 `schema_version: 1`、`kind: ticket_fare` 和原有 `prices` 数组，以增量字段交付合并卡片。不新增另一个余票卡片种类。按 `train_code + date + from_station + to_station` 精确合并，不能按数组顺序、相似站名或邻近日期拼接。

| 字段 | 含义 |
| --- | --- |
| `fare_status` | 票价单项：`success / partial / empty / failed / not_requested`。旧回执未提供时才回退旧 `status`。 |
| `fare_error` | 票价错误；顶层 `error` 同样保留票价错误以兼容旧消费端。 |
| `availability.status` | 余票单项，取同一组状态；成功也可能全部席别“无”，不等于有票。 |
| `availability.seats` | `{seat, availability, raw_value, status}` 数组；`seat` 为归一化席别名，另三个字段保留状态信息。 |
| `availability.sources / fetched_at / error / note` | 余票自己的来源、UTC采样时刻、错误和说明。不能使用价格的时间冒充。 |
| `availability.start_time / arrive_time / duration` | 余票接口原始区间时刻。与票价接口冲突时另外提供 `time_discrepancy` 字段名列表，保留两份值。 |
| 顶层 `sources / fetched_at` | 继续表示票价来源与采样时刻。余票在嵌套字段中；只返回余票时顶层来源为空。 |
| 顶层 `status` | 合并状态：两项完整成功为 `success`；一项有有效数据但另一项失败/不完整为 `partial`；两项空为 `empty`；没有有效结果且有失败为 `failed`。只请求一项时沿用该项状态。 |

`prices[].amount` 仍是元的十进制字符串，缺失为 `null`，不填0元。席别余票的状态：

| 原值 | `availability.seats[].status` | 展示建议 |
| --- | --- | --- |
| `有`、正整数 | `available` | 有票或原始张数 |
| `无`、`0` | `unavailable` | 无票 |
| `候补` | `waitlist` | 候补；不可标为直接有票 |
| 空、`--`、不认识的值 | `unknown` | 未提供；不可标为无票 |

旧的纯票价历史回执没有余票字段，继续按旧契约显示；不把未查询过余票解释成无票。无法确认相同身份的回执保留独立结果，不强行合卡。

## 前端接入

1. 将票价与余票作为同一张卡片的两项内容，标题可用“票价与余票”。席别表采用“席别｜票价｜余票”，按席别名关联两组数据，取并集；某项缺失显示“未提供”。不要按数组下标关联。
2. 单项错误在卡片内独立显示，保留另一项成功数据。例如余票超时仍显示真实价格，票价失败仍显示候补或余量。用 `fare_status` 判断金额是否完整，不能因顶层 `partial` 就宣称价格缺失。
3. 保留价格口径，以及两项各自的来源和采样时间。接口到发时刻不代表实际运行状态。票价存在不证明有票，候补不保证兑现。
4. 多车次、多日期按完整身份分别显示，不跨日期合卡；重开历史、复制、分享都保留两项事实和错误。正文降重只有在两项结构化事实确实对应时才移除重复行，未识别说明仍保留。
5. 未识别新增字段的旧客户端仍能读原有价格与文字余票回执。本轮不改变聊天路径、请求或SSE事件；客户端需完成新字段解析后才真正合并视觉卡片。
