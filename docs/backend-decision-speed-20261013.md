# 决策阶段提速：第一轮

日期：2026-10-13。只改 Main 决策层；本轮不优化业务缓存或检索流程，不改前端、release 和聊天协议。

## 已落地

1. 站名匹配改为枚举输入的 2–8 字符片段，查询现有站名集合；避免每次遍历全部 3384 个站名。同长度顺序、长名覆盖短名及站名集合变化的行为保持一致。同一句输入的站名与站名列表共用一次匹配结果。这不是跨请求缓存。
2. 增加闭合知识决策树叶子：独立车型技术参数、型号比较、车型介绍以及重联等少数铁路术语定义。整句必须符合受控句式；任何历史对话、日期、运行状态、车组编号或复合诉求不匹配时仍交出。比较句的第二型号保留在 extra，原问句仍交给生成层。
3. 叶子由 Main planner 调用，输出仍为 general / knowledge，planner 仍为 deterministic。LM 不使用新叶子。`CLOSED_KNOWLEDGE_TREE_ENABLED=false` 可单独停用；`FASTPATH_ENABLED=false` 同时停用原快路径与新叶子。未修改用户的模型选择与现有精简提示开关。

旧 fastpath 对知识问题的交出行为仍保留；新叶子在站点加载与原快路径之前检查，未匹配时继续原流程。这次没有移植旧决策树包，也没有修改冻结语料以配合实现。

## 实测与口径

| 范围 | 结果 | 限制 |
|---|---|---|
| 本地规则决策 | 192 条冻结输入，交替新旧顺序各 12 轮、各 2304 次调用；平均 0.509 → 0.078 ms，下降约 84.6%；p95 1.260 → 0.447 ms | 已加载站点库，不含模型、网络或启动；新旧 FastPlan/Defer/槽位逐条相同 |
| 新知识叶子 | 冻结语料额外接管 8 条，general/knowledge 与标签一致；另测正反例、禁用开关及 LM 保护 | 原标签的 route=llm 是旧路径记录，未改写；接管数不等于准确率 |
| 型号比较问句 | 原完整提示云端决策两次平均约 3493 ms；新叶子本地调用 200 次平均约 0.048 ms，决策模型调用为 0 | 仅一类窄问法的收益，不能外推到全部问题；生成阶段仍需模型 |
| 精简提示候选 | 4 个探针、两轮、共 16 次真实模型调用：现有提示平均 6792 ms，精简提示 3833 ms；基础意图/性质符合探针期望为 7/8、8/8 | 非正式黄金集评估；存在长尾波动，未检验完整槽位正确率，未启用为默认配置 |

**尚未证明整个决策阶段平均降低 30%。** 本地微秒级收益与云端秒级收益必须分开。新叶子减少了部分模型调用，但多数未命中请求仍需模型。精简提示的 43.6% 小样本均值也不作为达标结论。

云端探针中包含原快路径可处理的问句，仅用于隔离比较模型提示，不代表真实请求都会调用模型。全部测试沿用已有供应商配置，证据不包含密钥。

## 回归与工程边界

运行规则快路径、冻结语料、多轮槽位、多日期服务、流水线性能、日期解析和两组新增测试，共 8 个套件。完整结果在 `.ai/decision-speed/20261012-v1/regressions.json`，日志同目录。

流水线套件两项旧预取测试使用“明天”，但现有生产策略已禁止预取未来交路。第一项在旧规则快照下也能复现失败。本轮将这两项用于验证并发/复用的测试日期改为“今天”，保留全部断言；没有放开未来查询或修改预取实现。

未改缓存 TTL、工具并发、铁路数据接口、SSE、展示 schema 或启动地址。无需前端适配。现有事故保护、多车次和多日期调度继续由原模块负责。
