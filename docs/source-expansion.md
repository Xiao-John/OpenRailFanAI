## 二、写代码前必读的硬约束（都是实测出来的反直觉结论）

1. **Overpass 必须用非浏览器 UA**：✅本机复核 —— `overpass-api.de` 用 Chrome UA → **406**，
   换 `curl/8.7.1` → **200**；镜像 `maps.mail.ru/osm/tools/overpass/api/interpreter` 两种 UA 都 200。
   → **首选 mail.ru 镜像 + curl 风格 UA + 退避重试**（官方 de 成功率约 25%）。
2. **坐标系别混用**：Overpass/OSM/GTFS = **WGS84**，高德/腾讯 = **GCJ-02**，混用偏 **50–500m**。
3. **GitHub 只有三条可用通路**：`github.com`、`raw.githubusercontent.com`、**release 资产链** 全部
   **HTTP 000**（境内阻断）；可用的是 `api.github.com`（查版本）、`ghfast.top`（取 release 资产）、
   `cdn.jsdelivr.net`（取仓库文件，**整仓库 >50MB 会 403**）。
4. **12306 三个陷阱**：`bigScreen` 参数名是 `train_station_code`（写错 → 200 + `status:true` + `data:[]` 静默失败）；
   `getCarDetail` 外层 `status=0` 时 `content.data` **仍可能有完整数据**（判据看 `content.data`）；
   短时间高频会限流（`M0003 系统忙`）。
5. **EmuSearch 两个陷阱**：分页参数是 **`pagenum`**（不是 `page`）；`emu_detail.php` 详情页**已死**（空壳）；
   姊妹站 `cr400bf.passearch.info` 是**陷阱**（7 次实测响应字节级一致，库已空）。
6. **jprailfan 表单挂 reCAPTCHA v3**、单页 3–5s → 只做低频内部检索 + 本地缓存。
7. **轨上名录 10MB 别实时下载**（GitHub Pages 境内约 5 分钟；走 jsDelivr 快得多）→ 后台任务落库。

## 四、合规红线（统一执行）

1. **AGPL-3.0 传染**：轨上名录 README 明确"不得商用" → 本地使用可以，**对外分发其数据可能触发 AGPL 义务**。
2. **著作权**：jprailfan 里程表源自《铁路客运运价里程表》；照片著作权属摄影师（有 `photo_author`）。
3. **无 LICENSE**：GTFS、China_Railway_GIS → 权利不明，仅内部使用。
4. **个人小站不当生产后端**：EmuSearch / 下关站 → ≤1 req/s + 本地缓存 + 可识别 UA + 失败即退避。
5. **社区数据 ≠ 权威**：配属/车型参数均人工维护 → **一律标注来源 + 抓取时间戳**，冲突时如实呈现分歧。
6. **绝不做**：绕过登录/付费/验证码；批量抓 12306；整表对外分发里程表。

## 六、配属能力：**未来研究**（2026-09-15 已定暂不接入）

### 概念先分清（这是最容易混的地方，实测字段级确认）

| 概念 | 含义 | 谁能给 |
|---|---|---|
| **车组号** | 这一组车是谁（`CR400BF-A-5159`） | ✅ **12306 官方** `getCarDetail`（已接入）+ rail.re |
| **担当** | 这趟车由哪个客运段值乘 | ✅ 12306 `getDeptByTrainCode`（`deptName=上海客运段`） |
| **配属**（车的户口） | 这组车归哪个**局 / 动车所**，含改配史 | ❌ 12306 无任何局/段/所字段（`getCarDetail` 全部 7 个字段实测均为车型/车组号/车厢/图）；rail.re 也没有 → **只有车迷配属库有** |

12306 侧只到"段级"（大屏 `jiaolu_dept_train=上海动车段`），且是**交路口径**，不等于车组级配属。

### 候选来源（已实测，但**本轮不接入**）

| 来源 | 能力 | 实测 | 不接入的原因 |
|---|---|---|---|
| EmuSearch `emu.passearch.info` | 车组号→配属路局/**动车所**/厂家 + **改配史**；支持按车型/路局/所/厂家查；`pagenum` 分页 | 字段与结构已复核（`5159 → CR400BF-A｜上海局集团｜上海虹桥｜中车长客｜郑州局郑州东改配`） | **个人车迷自建站、众包+人工汇编**；为一个次要能力去依赖/抓取个人站点不合算（见下"决策原则"） |
| 轨上名录 `leaf2006/CR-Locomotive-Allocation` | 31,789 条（含 3 万余条**普速机车**）+ 实车照片 | 静态 JSON 10MB，镜像可达 | **AGPL-3.0 + README 明确"不得商用"**；照片著作权属摄影师 → 对外分发会触发许可证义务 |
| 姊妹站 `cr400bf.passearch.info`、`loco.passearch.info` | — | 实测**库已空 / 未上线**（响应字节级一致） | 不可用 |

### 决策原则（本次已定，后续同类问题照此办理）

1. **不为次要功能牺牲原则**：配属属"锦上添花"（用户问得少，且与"担当"易混），
   而依赖个人站点意味着把产品可靠性绑在他人业余维护的服务器与许可证状态上。
2. **12306 官方接口按"公开可用"对待**（公开接口、大量平台在用，无道德负担）——
   我们照常按需调用，只做**限流纪律**（并发/间隔/TTL 缓存），不做额外自我限制。
3. **对个人/社区站点仍保持礼遇**：低频（≥2s 间隔）、可识别 UA、本地缓存、标注来源与抓取时间、
   **不整表对外分发**。礼遇是工程与合规考虑，不是"不能碰"。
4. 将来若要做配属，优先路径是：**自建众包/人工维护的小型配属表**（只收录我们真正常问的车组），
   或取得 EmuSearch / 轨上名录作者书面许可后再接入；**不做**全量镜像对外分发。
