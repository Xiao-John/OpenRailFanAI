# 实际执行票价修复交接

2026-10-06。此前Main票价调用`queryAllPublicPrice`，返回公布票价。现默认改为售票页面使用的`leftTicket/queryTicketPrice`；旧票价数值不得继续视为实际购票执行价。

## 已实现

- 从指定乘车日期、实际出发/到达站的售票记录取得内部`train_no`、区间站序和`seat_types`，再查询对应执行票价。金额直接取上游人民币字段，不从公布票价计算折扣。
- 车次和实际区间精确匹配，保留日期和每条记录归属。支持现有最多10车次×10日期的调度，流式和块式沿用统一投影。
- 执行价失败、缺少内部绑定或无有效金额时明确失败，**不调用公布票价接口补位**。未找到精确售票记录仍为空结果，不能据此判断停运或无票。
- `ticket_fare`仍为版本1，追加`fare_basis=executed|published`。正文与`note`明确区分口径，原字段继续兼容。执行价是查询时价格，购票提交时仍可能变化；价格不代表有票。
- 当前只改变Main；LM专属轨道及旧公布票价调用保持原状。

## 公布票价与本地词典

明确包含“公布票价/基准票价”的查询走本地`published_fare`表，网络请求数为0。该表键包含车次、实际区间、适用期和席别，数据还必须带人民币金额、来源和原始采样时间。适用期外或没有有效来源时按缺失处理，不根据GTFS里程推算价格。

原库实际没有票价表或票价记录。此次建立读取与建库表结构，**没有凭空补齐公布票价数据**；当前查询会提示“本地词典暂无……，未发起网络查询”。需要可信的公布票价数据集才能形成覆盖，不能宣称现有词典已能回答全路公布票价。

GTFS单独更新继续保留该表；新软件包若含公布票价数据及较新的`meta.published_fares_pulled_at`，启动合并时可更新该表，已有资料较新时保留本地版本。自动包内导入依赖软件更新交接中的独立路径配置。

## 前端接入

- 执行价卡片标识“实际执行票价”；参考价标识“公布参考票价”。优先读取`fare_basis`，正文和`note`仍提供兼容标识。
- 未识别该字段时保留原说明，不把公布票价默认标成执行价；历史回复不能凭新默认规则重新解释，旧`queryAllPublicPrice`来源属于公布价。
- 失败和无记录保留原车次/日期；不得用参考价格伪造可购金额，也不能从无座价格推断无座有票。

本次未修改Android、WebUI或安装包，也未重启共享服务。客户端需连接包含本次修复的后端，并确认当前服务已加载本次代码；本次未重启共享服务。

## 验证

13项新增离线测试覆盖售票参数、元与分字段、邻站/其他车次过滤、错误不回退、缺车次不扩散请求、空结果、缺失金额、公布价零网络及适用期、软件包带参考价和LM兼容。

真实匿名执行票价查询：G1北京南→上海虹桥，2026-10-07/08二等座661元、一等座1058元、商务座2315元；2026-10-09分别626/1033/2156元。三个日期均保留独立归属，实际售票价格出现跨日期变化。此前公布价为二等795元，属于不同口径。真实验证未调用公布票价工具、云模型或私密配置。

实现依据为12306官方售票页JavaScript中的`queryTicketPrice`调用和同次原始响应；价格字段仅取官方页面展示字段，不把内部“分”字段当“元”。证据：`.ai/executed-fares/2026-10-06-v1/`。

跨日补证据：10月7日郑州→北京西Z502的售票行始发日期为10月5日，按乘车日10月7日传参成功取得票价。官方售票JavaScript调用使用查询乘车日，未以始发日期替换。卧铺金额当前按接口席别返回，未细分上/中/下铺，正文及说明明确标注该限制。

应用到当前项目后，13项新增测试及14组既有回归通过；既有网络边界采用原任务明确记录的离线夹具，不把夹具当作真实接口证据。
