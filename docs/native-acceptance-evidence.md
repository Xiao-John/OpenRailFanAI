# 原生验收运行证据与采集基准

本协议补充现有验收流程，不改变设计、容差、设备示意排除规则或产品界面。

## 文件责任

H 本轮负责 `scripts/acceptance.sh`、原生运行归档、日志提取和索引消费端。
L 负责 Kotlin 夹具的采集基准输出、历史夹具边距修正及产品界面。
双方不同时编辑对方负责的文件。

## 正式入口与归档

继续使用 `./scripts/acceptance.sh --main-compose`。每次调用创建
`acceptance/runs/<run_id>/manifest.yaml`，保存本次测试结果、日志、采集文件、
对照图与索引副本，并记录文件 SHA-256。测试统计读取归档中的逐项测试结果。
后续单项诊断覆盖 Gradle 输出时，已有运行归档不受影响。

脚本只使用本次运行更新的测试结果与唯一九状态采集日志。
旧日志、缺少测试结果或含失败测试时，不能继续提取旧截图作为本次证据。
顶层 `failed` 状态与记录内部的 `unmeasured` 内容分别统计。

## Kotlin 夹具输出协议

每个状态的正式截图输出恰好一条日志：`NATIVE_BASIS|<state>|<base64>`。
末段为 UTF-8 JSON 的标准 Base64，不换行；状态名称沿用九状态现有标识。
在同一稳定布局中先取基准和节点矩形，再截图；采集后才执行交互操作。

JSON 字段如下；值由实际测量产生，不写死系统边距或滚动位置：

| 字段 | 类型及要求 |
| --- | --- |
| `schema_version` | 整数，当前为 `1` |
| `coordinate_origin` | `capture_root` |
| `phase` | `before_interaction` |
| `root_rect_px` | `[x,y,width,height]`，相对截图原点，当前 `[0,0,390,844]` |
| `content_tag` | 真实应用内容容器的语义标记；同时输出其 `NATIVE_RECT` |
| `content_rect_px` | 内容容器的 `[x,y,width,height]`，相对截图根节点 |
| `system_insets_platform_px` | 真实系统边距 `[left,top,right,bottom]`，平台物理像素 |
| `system_insets_applied_px` | 在夹具局部密度中实际应用的边距，同顺序，局部像素 |
| `platform_density` | 设备密度 |
| `local_density` | 当前采集组合的密度 |
| `font_scale` | 当前采集组合的字体缩放 |
| `scroll_mode` | 分项列表使用 `list`；连续滚动容器使用 `continuous`；确无滚动容器时使用 `not_scrollable` |
| `scroll` | 滚动对象；确无滚动容器时为 `null` |

`schema_version` 仍为 `1`；本次增加明确的滚动模式分支，现有 `list` 记录保持兼容。

- `list`：`scroll` 对象必须记录非负整数 `first_visible_item_index`、
  `first_visible_item_offset_px`、整数 `viewport_start_px`、`viewport_end_px`，
  以及非负整数数组 `visible_item_indices`。索引对应实际列表项；视口偏移沿用列表布局坐标。
- `continuous`：`scroll` 对象必须记录整数 `scroll_offset_px`、`scroll_max_px`、
  `viewport_start_px`、`viewport_end_px`。满足 `0 <= scroll_offset_px <= scroll_max_px`；
  视口起止坐标相对截图根节点，满足 `0 <= viewport_start_px < viewport_end_px <= 844`。
  最大偏移为 `0` 表示本次内容无需滚动，不等同于不存在滚动容器。
  该模式不要求且不得声明列表索引字段。历史页的 `verticalScroll Column` 使用此模式。
- `not_scrollable`：`scroll` 必须为 `null`，只用于确无滚动容器的场景。

连续滚动校验通过只证明偏移范围与视口记录一致。会话行可见性另由稳定行标识、
实际行边界、视口相交及菜单遮挡记录证明，不由滚动偏移或虚构索引推导。
缺失行级证据保持未测；不能为了省略记录将实际滚动容器声明为不可滚动。

密度换算的检查关系为：平台边距 × 局部密度 ÷ 平台密度 ≈ 实际应用边距，
允许整数换算造成的不超过 1px 舍入差。真实内容容器边界必须与对应节点测量一致。

基准 JSON 的矩形使用 `[x,y,width,height]`；既有 `NATIVE_RECT` 日志协议使用
`[left,top,right,bottom]`。输出内容容器日志时必须将宽高加到起点，不能直接填入右边界和下边界。
回到底部会改变阅读状态及建议项，应在独立初始化的场景中验证换日期操作。

时刻页正式设计首屏固定为首项索引 `0`、首项偏移 `0`；独立重复诊断也使用这一基准。
复制触摸验证在正式截图及矩形记录完成后滚入控件，再检查完整触控边界与回调。
不得为了让屏外操作区显示完整而改动正式截图的阅读位置；首屏中的裁切保持真实记录。

缺少、格式错误或内部不一致的基准会进入索引的 `unmeasured`。
几何偏差已失败时仍保留这些未测原因；不得将顶层未测状态数为零理解为没有缺失证据。

## 验证范围

### 独立触控下限

版本 `2.3.0`、测量映射版本 `5` 将项目既有的最小点击区域要求显式声明为
`minimum_touch_px: {width: 44, height: 44}`。当前正式采集固定局部密度为 1，
该值只用于本采集基准中的触控宽高检查，不从设计区域宽度或高度推导。
每个声明 `size_rule: minimum` 的映射必须提供独立下限；缺失或无效时保持未测。

正式视觉矩形比较仍读取设计目标和既有 `compare_fields`，容差仍为 2px。
索引触控记录的 `requirement_source` 指向映射中的显式下限。
不得用触控合规证明视觉尺寸合规，也不得用扩大隐形触控边界替代可见边界测量。

例如归档 `20260930T174225-04f35f20` 中技术日志入口实测 313×44px，满足独立
44×44px 下限。旧规则将设计区域宽 358.77px 当作最低触控宽，产生了不成立的
45.77px 触控缺口。当前详情夹具嵌在时刻卡片内，既有映射只检查高度；
面板、来源行、数据行和日志入口的视觉宽度继续明确标为未测，不因此标为通过。
同样，实际高度只有 40px 的回到底部入口仍低于 44px 下限，不能被此修正放行。

### 时刻页底部安全区锚定

索引消费端版本 `2.2.0`、测量映射版本 `3` 为时刻页的 `fixed_input` 与
`suggestions` 显式使用 `vertical_anchor: safe_bottom`。两项属于固定底部操作组；
其余流式内容、顶栏、卡片及操作图标文字继续使用既有坐标规则，不统一平移。

原始设计矩形保持不变。先按应用画框宽度换算到 390px，再保留各元素宽、高、
横坐标及其距设计应用画框底部的间距；仅将纵坐标锚定到实测安全内容区底部。
建议区与输入栏之间的设计间距随此规则保留。安全内容区基准必须通过现有校验，
且上下边界分别与根节点及实际系统边距吻合；不能通过改变容器边界追随当前控件位置。
无效基准或目标无法放入安全内容区时，该项保持未测。

计算规则为：目标根节点纵坐标 = 实测安全内容区底部 − 设计底部间距 − 设计换算高度；
最终索引目标纵坐标再减去实际坐标原点的纵坐标。
索引同时保存 `original_expected_px`、校准后的 `expected_px` 与 `vertical_anchor` 依据。
目标只依赖设计矩形、真实安全内容区域与坐标原点，不读取待验收控件的当前位置。

在归档 `20260930T135029-088ae63a` 的基准下，安全内容区为根节点 `y=24..796`，
输入栏校准目标为根节点 `y=740.29`、高 `55.71px`，底部为 `796px`；
建议区目标为根节点 `y=682.65`、高 `42.27px`，与输入栏间距 `15.37px`。
相对顶栏原点 `y=24`，两者的目标纵坐标分别为 `716.29px`、`658.65px`。
这些数值仅解释该归档，产品不得写死该设备的 24px 或 48px 系统边距。
当前输入栏仍有纵坐标约 `10.29px`、高度约 `2.29px` 偏差；建议区仍有纵坐标约
`8.65px` 偏差。安全区校准不代表这些残余偏差或整个时刻页验收通过。

版本 `2.2.1`、映射版本 `4` 将相同规则用于交路页的共享 `fixed_input`。
交路页其他元素及历史页底部元素仍按其既有映射分别审查，不能推导通过。

### 操作区边界诊断

LR4 确认 `result_actions` 设计区域含空白，而 `result-actions-visible` 是
Compose 图标与文字节点布局边界的并集，两者不是同口径的可见绘制边界。
版本 `2.2.1` 将该映射标为 `comparison: diagnostic_only`；原始目标与实测值
保留在 `measurement.diagnostic_geometry`，并声明 `acceptance_eligible: false`。
其差值不再进入正式 `diff_px` 或布局失败清单；缺失同口径目标仍进入 `unmeasured`。
这项调整不能将操作区标为通过，也不改变任何正式比较的容差。

LR4 使用最大 RGB 通道小于 175 的像素边界作诊断，该阈值不是正式验收规则。
半开区间的组间隙应按后一组左边界减前一组右边界计算。
H 在归档 `20260930T165300-6170e288` 复算：设计前组右边界为 177、后组左边界为
222，间隙为原图 45px；实际前组右边界为 96、后组左边界为 119，间隙为 23px。
LR4 报告的实际 22px 需更正。阈值从 175 改为 160 时实际间隙会变成 28px，
说明现有像素诊断受颜色及抗锯齿影响，尚不能直接提升为正式间距验收规则。

H 的脚本回归只证明旧证据隔离、测试结果归档与基准校验机制。
九状态基准、原生界面交互及视觉结果须由 L 完成生产端记录后通过正式入口验证。
本轮不以脚本回归宣称产品视觉通过。

### 历史页底部安全区与遮挡契约

消费端版本 `2.3.1`、映射版本 `6` 将历史页的 `action_panel` 和
`cancel_action` 显式设置为 `vertical_anchor: safe_bottom`。
它们与固定底部链接共用真实安全内容区底边；搜索、新建、分组及顶栏不统一平移。
完整目标、坐标约定与限制记录在 `.ai/reports/HR13-history-bottom-contract.yaml`。

归档 `20260930T220547-36bbe8fb` 的安全内容区为根坐标 `y=24..796`。
据原始设计，操作面板目标为根坐标 `y=535.68`、高 `147.93px`；
取消按钮为 `y=691.30`、高 `54.75px`。两者相对顶栏原点 `y=24` 的
目标分别为 `511.68px`、`667.30px`，比旧顶部定位目标上移 `23.37px`。
保留面板至取消按钮 `7.68px`、取消按钮至底部可见内容组 `21.13px` 的设计间距。
这些数值用于解释归档，产品使用动态安全边距，不能写死本例设备数据。

底部可见内容组的空间参考为根坐标 `[30.74,767.18,330.44,25.94]`。
它不等于全宽 `history-fixed-bottom-links` 父容器，也不等于纯文字节点并集。
该参考暂不纳入正式矩形映射；对应绘制并集和图标轮廓仍未测。
独立触控范围至少为 `44×44px`，可见内容无需在隐藏触控扩展中严格居中，
不得缩小触控范围或越过真实安全内容区来对齐可见内容。

正式历史场景保持菜单展开，并在截图前记录两枚底部图标、两段标签、分隔线、
操作面板、取消按钮的同坐标边界。底部各节点须完整位于安全内容区，
与不透明面板及取消按钮交集面积为零；半透明页面遮罩另外记录。
语义节点存在、名称含 `visible`、文案匹配或矩形与视口相交均不能单独证明完整可见。
图标布局边界也不能替代墨迹边界。

该归档中取消按钮 `y=714..769`，底部内容节点 `y=754..774`，存在 `15px` 遮挡。
原始 `NATIVE_HISTORY_GEOMETRY` 包含布局诊断；在 `2.3.1` 版本中，提取脚本尚未
将其消费为正式自动可见性结果。该旧版证据仍保持未测，不因存在诊断日志而标记通过。

旧归档中面板及取消按钮的通过结果只适用于旧坐标目标，校准后需重新验收。
历史归档保持不变；下一次正式入口记录新版本、新目标及残余偏差。

### 历史页可见性消费端

版本 `2.3.2` 补齐上述诊断的消费流程。提取脚本将同次正式日志中的唯一
`NATIVE_HISTORY_GEOMETRY` 保存到历史状态的 `history_diagnostics`；重复或非法
对象阻止该次提取，缺失对象不能回退使用此前运行。

消费端先核对诊断中的连续滚动偏移、最大偏移与视口起止是否匹配正式采集基准，
再读取两段标签、两枚图标及分隔线的根节点布局矩形。
有同次 `NATIVE_RECT` 时两份坐标必须一致；缺失、非法或重复节点保持未测。
操作面板和取消按钮均必须有实测边界，以保证正式场景仍为菜单展开。

正式索引的 `measurement.history_footer_visibility` 保存安全内容边界、
不透明覆盖物边界、每个节点的完整包含结果及遮挡交集面积。
任何节点超出安全内容区或与菜单不透明区域相交，都会进入 `failed_visibility`，
使该状态为失败；缺少证据使其保留未测。该判定不使用2px几何容差抹去遮挡。

此检查只证明布局范围内不存在上述不透明遮挡，不证明图标墨迹或设计几何对齐。
固定底部可见内容并集、图标轮廓和其他既有未测项继续独立保留。
归档 `20260930T220547-36bbe8fb` 的只读复算识别出五个被取消按钮遮挡的节点：
两段标签面积为 `1050px²`、`840px²`，两枚图标均为 `300px²`，分隔线为 `15px²`。
该复算未重写正式索引；新的正式结果由下一次 `./scripts/acceptance.sh --main-compose` 生成。

版本 `2.3.2` 已在正式运行 `20260930T231703-74905886` 消费生产端记录：
修复后的五个节点均在安全内容区内，与两块不透明菜单区域的交集面积均为零。
该结论只证明 LR12R 的遮挡条件通过，整体运行仍为 `not_accepted`。

### 阅读提示的触控与绘制分离

版本 `2.3.3`、测量映射版本 `7` 对回到底部入口分别记录
`return-to-bottom` 的透明点击容器与 `return-to-bottom-visual` 的可见气泡。
前者使用 `comparison: touch_only`，只检查显式 `minimum_touch_px`，不计算设计视觉差值；
后者继续按照 `return_to_bottom_cue` 原始设计目标检查气泡宽高，容差保持2px。
原生夹具同时采集两枚标签，缺少可见气泡证据仍为未测。
扩大透明点击范围不能替代气泡对齐，也不改变已有未测内容。

同版根据 LR11 诊断，将历史页 `history-header` 父容器与设计视觉区域之间的比较
标为 `diagnostic_only`，保留原始目标、实测矩形及缺失同口径目标的原因。
44px触控父容器不再被要求缩成40.34px的视觉区域；顶栏视觉目标和墨迹仍待测，
不能因此将顶栏或历史页标记通过。

### 阅读追问按钮的可见并集

版本 `2.3.4`、映射版本 `8` 将 `reading-followup-visual-union` 定义为同次首屏采集的两枚 `result-followup-*-visual` 边界并集。任一子节点缺失时不输出并集；不能使用 44px 高的触控父行替代。此边界是胶囊背景与边框的布局范围，不代表文字或图标墨迹。两枚原有触控标签分别检查 44×44px 最小范围。

### 已记录的阅读输入栏冲突引用

映射版本 `9` 按 `design-targets.json` 既有冲突解决规则，对阅读状态固定页脚高度引用完整应用画板的 `train_schedule.fixed_input`。原始补充稿目标仍随每项记录保留，新增 `design_reference` 记录来源矩形、画板、缩放与规则。消费者仅接受与已记录 `resolved_reference` 相同且属于当前元素的冲突引用，不能任意选择另一张图的目标。完整应用画板宽406，输入高度58，390换算为55.71px；补充模块宽454，输入高度50，换算42.95px，两者差12.76px。此修正不改变普通输入栏布局，也不解决阅读表格形态的待确认事项。

### 文字墨迹尺寸与文字行框分离

消费端版本 `2.4.0`、映射版本 `10` 为明确声明的八个文字叶节点增加
`comparison: painted_size`，只比较文字墨迹宽高。设计矩形只是原图选择区域，
Compose 文字矩形包含行高和字体留白，两者的旧差值保留在 `layout_diagnostic`，
不再冒充字形尺寸差。其他矩形映射和既有2px容差不变。

同次正式截图前输出 `NATIVE_NODE_TEXT|状态|语义标签|UTF-8文本的Base64`。
只有唯一叶节点文本与映射的 `expected_text` 完全相同、采集基准有效、文字行框
完整处于实测裁切容器内时才读取墨迹。不存在叶子文本、无前景像素、区域越界、
阈值不稳定或不完整可见均保持未测，不能使用旧运行补齐。

`native_paint_metrics.py` 对设计和实现使用相同的三组前景分割阈值：

- 深色文字：`R<(80,100,120)`、`G<(110,130,150)`、`B<(155,175,190)`。
- 辅助文字：蓝灰色分量满足 `B-R>(18,12,8)`、`G-R>(4,2,0)`、

- 红色文字：`R>1.4G`、`R>1.4B`、`G<(160,180,200)`。

括号内依次为严格、基准、宽松阈值。边界采用半开像素区间；原始图片不缩放、
不修改，不另存裁切图。设计墨迹宽高按原有画板宽度换算到390px。
索引保存三组双方墨迹边界、像素数量、原始选择区域及阈值规则；正式差值采用
严格对严格、基准对基准、宽松对宽松三组配对中的最大值，不能选择最小差值的阈值。
九种跨档配对仍作为诊断保存，不能把阈值定义差异当作应用偏差。任一侧三组结果的尺寸变化
超过2px，保持未测。这个检查只证明墨迹尺寸，不证明字体身份、字形轮廓、
文字位置、图标或整页验收通过；未覆盖的文案叶节点仍独立保留未测。
