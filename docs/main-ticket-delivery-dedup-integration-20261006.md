# Main 票价与余票单渠道交付接入

日期：2026-10-06。依据[后端单渠道交付交接](backend-ticket-delivery-dedup-20261006.md)。

## 客户端改动

- Main Android 在首次聊天请求前读取 `/api/sessions` 的 `supported_client_capabilities`。
- 仅当后端明确声明 `ticket_fare_availability_v1` 时，聊天请求才附加同名 `client_capabilities`；探测失败或旧后端不声明时发送空列表，保留旧回执兼容。
- 能力列表在当前 `ChatRepository` 生命周期内缓存；未知能力不转发，不进入供应商配置或模型提示。
- `ChatStreamRequest` 序列化能力列表，保持原有聊天路径、SSE 和取消行为。

## 展示边界

客户端已能解析并展示合并票价/余票卡片。后端声明能力后，结构化结果完整覆盖的价格表、余票表和重复来源由后端不再交付正文；客户端保留未覆盖说明、澄清和未知协议的降级路径。空正文仍以 `done.display_results` 渲染卡片，不视为模型连接失败。

历史消息不会被后端重新写入；历史重复内容继续由客户端按严格身份和事实覆盖关系处理。LM 不发送该能力声明。

## 验证边界

Kotlin 编译与差异检查通过。未启动模拟器、未进行真实多车次端到端查询、未重新构建或发布 APK。本次仅修改客户端请求能力声明，后端交接中的共享工作树与服务不受覆盖。

下一轮实测需检查新后端声明、旧后端兼容、无正文结构化回复、单项失败、多车次多日期、历史重开以及复制/分享。
