# M：多轮与日期语料提示词

请生成 OpenRailFanAI 新决策树的上下文和时间语义候选。你负责批次 M，目标 100 条，采用统一候选格式。

先读 AGENTS.md、docs/ui-design-boundaries.md、docs/backend-parallel-development-boundaries.md、docs/intent-corpus-expansion/CONTRACT.md 和本提示词。其后不读代码、旧 SPEC、已有语料、测试、其他批次或旧树，不联网。只写 `.ai/intent-corpus-v1/M/`，已有产物则另建 M-run2，不改原文件。

建议覆盖分配：40 条换对象/换区间/话题切换，40 条日期与时段，20 条链式省略、助手实体干扰和真正不充分指代。数字是覆盖建议，不是迫使样本制造歧义的配额。

具体包括：

- 本次完整对象覆盖历史；只换起点/只换终点/改车型/改席别。
- 最近多轮含不同话题、车次和日期，不能跨轮逐槽位拼接。
- “这车”“那趟”在不同上下文的含义；有唯一用户证据与仅有助手答案的对照。
- 明确换日期与仅改时段、裸钟点、相对日期、中文公历日期、非法日期。
- 多对象对应不同日期、跨午夜以及历史相对日期锚点未知。
- 一次输入同时更正对象和日期，以及链式省略无法唯一恢复的情况。

至少 20 组 2–4 条最小对照（计入总数）；有多轮的样本 history 只用 role/content，旧到新，不含本次 message。每个继承槽位必须标 history_index 和 quote；助手消息中的实体不得当成可靠槽位来源。助手历史全部是合成，必须声明。

不要把“下午”变成“今天”覆盖旧日期。clock 固定写入样本，相对日期不使用运行当天。没有用户可见依据的历史时间戳、工具数据或话题绑定不得自行发明。日期锚点不明确时保留 time.raw、resolved_date=null 和具体歧义。没说日期与非法日期要分别标注。

多任务的明确部分仍保留在 tasks；省略句不能仅因为无关键词就标为无语义，也不能仅因最近出现车次就强行 resolved。需要澄清时写一句能消除歧义的问题，不生成问题的答案。

输出 `candidates.jsonl`（ID=M-0001…）、仅输入字段的 `inputs.jsonl`、`manifest.json`、`summary.md`。检查 JSON/ID/字段、来源索引和引用是否实际存在，检查 ISO 日期是否合法、相对日期与 clock 是否一致；不运行现有日期/分类实现来替你决定标签。manifest 记录文件哈希、覆盖统计、组数与疑难项。

结束只报告路径、条数、对照组数及尚缺的覆盖。不得修改或冻结既有语料。
