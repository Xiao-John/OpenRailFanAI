# 配置向导：后端协作边界

日期：2026-10-14。向导尚处设计阶段。本次只修改Main客户端的预设编辑；不修改后端现有速度、缓存、检索工作。

现有 `/api/providers`、`/api/providers/models`、`/api/providers/test` 已足够支撑预设摘要、模型选择和真实验证。客户端继续使用返回的预设，不覆盖用户已经更新的型号。

为了让向导在失败时定位正确步骤，建议后端以后在测试结果的现有ok/error旁增加可选、脱敏的诊断枚举，例如invalid_key、insufficient_quota、model_unavailable、service_not_enabled、region_mismatch、network、rate_limited、unknown；旧客户端仍能读取原字段。仅有明确证据才分类：429可能是限流，不等于没钱；403可能是权限/地域，不等于密钥错误。未知情况保持unknown，不由模型猜测。

不要求为向导新增自动注册、实名认证、付款或密钥创建接口；这些由用户在官网完成。客户端不能因为用户返回应用就向后端报告“充值成功”。余额查询是额外能力，当前未实现，不能伪造余额已验证状态。

后端目录中的空模型不必补成未经核实的名称；客户端读取授权模型后选择已核对候选，或者向用户展示可用列表。请在调整预设地址/型号时保留ID及现有覆盖优先级。新增地域或账户专属地址时，补充可读的配置要求，避免引导将其他地域的Key混用。

后续如增加服务商引导元数据，应独立于密钥与运行时模型配置，包含资料版本、来源、核对时间及手机流程审核状态。未通过手机完整流程的服务商不能标为“零搜索已验证”。
