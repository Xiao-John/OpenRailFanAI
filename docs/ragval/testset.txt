# ============================================================================
# RailFanAI · Agent 交叉验证测试集（RAG-EVAL TS v1）
# ============================================================================
# 本文件是"机器可读"的自动化测试集，不走手动测。每一行 = 一个用例，由执行
# Agent 逐条调用 /api/chat 采集证据，再由"主裁决 + 交叉复核"多个 Agent 独立评分
# 后交叉验证。格式声明与评分算法见 ../ragval/README.md（本文档配套文档）。
#
# 【行格式】一行一个用例，字段以竖线 `|` 分隔，共 9 列：
#   编号 | 分类 | 模式 | 我要问的话 | 我期待的结果 | 硬性可核对判定点 | 一票否决 | 权威核对源 | 备注
#
# 【多轮用例】"我要问的话"里用 `;;` 分隔每一轮（后续轮次作为上文语境传入 history；
#   同轮多个判定点仍用逗号分隔）。不需要 `;;` 的即单轮用例。
#
# 【判定点语法】用逗号分隔；每点是一句可由"外部核证 + 判官"独立核对的断言
#   （数值区间、格式、行为要求、日期锚定、站名/车次）。首列"编号"带 ★ = 核心必测。
#
# 【一票否决】命中任一即该用例直接判 0 分并计入"红线问题"，由两个判官独立确认。
# 【权威核对源】外部核证 Agent 用它做 ground-truth 对照：
#   12306=实时余票/时刻/经停权威；rail.re=车次↔车组交路；黄河客里=径路/里程；
#   知识=车型参数等常识（要求系统标注"据模型知识，未检索确认"）；工具链=答案须与
#   本次 tool_trace 返回的事实自洽。
#
# 分类代码：A交路担当 C余票 D时刻经停 E车站 F径路里程 B车型知识
#            G拍车 H资讯 I多轮 K老实安全
# 模式代码：real=依赖实时数据/境内网络；offline=纯知识或流程；hybrid=混合口径。
# 提问以"不懂技术的车迷"日常原话书写，允许口语、黑话、错字——但判定点必须客观可核对。
