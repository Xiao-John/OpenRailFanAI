## 1. D06 红线：次日图定值冒充今日实时值

### 现象（R1 证据）

> 问「G1 **今天**几点到上海虹桥」，答「**今天（2026-09-14）到达时间是 11:24**」，并称
> 「…次日（2026-09-15）同车次时刻表…**与此检索到的今日到达时间完全一致，可作为交叉印证**」。

### 根因（是我的回归）

上一轮为修 D02/D03「已发车丢经停/历时」新增了 `train_schedule._reference_schedule()`：
它在已发车时取**次日同车次**的时刻，并把结果**放进同一批检索事实**、只靠一句"参考"标注。
模型把次日 11:24 当成今日值，还自造了"交叉印证"。

### 根因之二（验证时新发现）：`emu.routing` 的记录时刻未标注

端到端验证（不经 LLM，直接看模型上下文）时发现：即使隔离了次日参考，
`11:24` 仍会出现在上下文里 —— 来自 `emu.routing` 的记录行
`2026-09-14 11:24 · CR400BFA-5159`，其中 `11:24` 是 **rail.re 的交路记录时刻**，
而它恰好与 G1 的图定到达时刻同值，**未标注时模型完全可以当成"今日到达时刻"**。
这正是 R1 里"与此检索到的今日到达时间完全一致"那句话的来源。

修复：`emu_routing` 逐行标注 `（交路记录时刻，非列车到发时刻）`，并在 note 里再次声明
"记录中的时间均为交路记录时刻…列车时刻请查 train.schedule"。

### 修复（结构性隔离，不靠措辞）

| 层 | 改动 |
|---|---|
| 工具 | **默认不下发任何次日时刻**；仅当 `include_reference=true`（由检索层按原话判断）时才取；下发时**独立成块**并带 `【非今日数据·次日图定（日期）】` 前缀 + "严禁用于回答今日时刻"的告示；`data.reference.is_today=False`；`data.today_times_available=False` |
| 检索 | 仅当问句含「经停/停靠/经过哪些站/途经/站序/全程/历时/多长时间/要多久/几个小时」时才置 `include_reference=true` |
| 生成 | prompt 新增三条硬规则：**跨日期绝对禁止**（非今日数据不得回答"今天几点"）、**禁止自造印证**（不得声称"完全一致/可交叉印证"）、**截断必须声明** |

### 验证

`test_r1_fixes.py`：
- `test_departed_does_not_leak_next_day_times_by_default` —— 默认路径文本中**不出现**次日时刻，且含"不可得"
- `test_reference_only_when_asking_stops_and_clearly_labeled` —— 问经停时才有，且带 `【非今日数据` 与"严禁"
- `test_retrieve_sets_include_reference_only_for_stops_questions` —— "几点到"关闭、"经停哪些站"打开
- `test_cross_date_and_cross_check_rules_in_prompt` —— 三条硬规则确实进入 prompt
- `test_emu_routing_labels_record_time_not_train_time` —— 交路记录时刻已显式标注

**端到端提示词级复验（不经 LLM，直接检查模型可见上下文）**：

| 问句 | 次日参考出现 | 【非今日数据】标注 | 11:24 已标注为记录时刻 |
|---|---|---|---|
| G1 **今天几点到**上海虹桥？ | ❌ 不出现 | —（无参考可标） | ✅ |
| G1 都**经停**哪些站？ | ✅ 出现 | ✅ | ✅ |

## 2. 截断冒充缺失（C02/C04）

### 现象与根因（三层截断）

| 层 | 位置 | 问题 |
|---|---|---|
| ① 工具 | `ticket_query` `shown = trains[:limit]`（默认 10） | 53 趟只渲染前 10 趟（按发车时刻排序 → 全是上午），**晚间车次根本没进上下文** |
| ② 生成 | `generate` `text[:900]` | 事实文本被硬切，连"共 53 趟"都可能被切掉 |
| ③ 语义 | 只给文本、没有结构化字段 | 模型只能"看列表数数"，没有 total / 筛选 / 聚合可用 |

C04「明天**晚上**还有二等座吗」因此答"尚未显示晚间车次"——**不是幻觉，是信息丢失**。

### 修复

**① 集合运算移到工具侧（`ticket_query`）**
新增参数并支持组合：`after_time` / `before_time`（发车时段）、`seat`（席别）、`train_type`（车种，支持多前缀如 `K,T,Z`）、`limit`；结果按发车时刻排序。
检索层从 **slots + 用户原话** 解析这些条件：

| 用户表述 | 工具参数 |
|---|---|
| 早上/上午 · 中午 · 下午 · 晚上/夜里/傍晚 · 凌晨 | `after_time`/`before_time`（如"晚上"→ 17:00–24:00） |
| 商务座/一等座/二等座/软卧/硬卧/硬座 | `seat`（business / first_class / second_class / soft_sleeper …） |
| 高铁 · 动车 · 城际 · 普速/绿皮 | `train_type`（G / D / C / `K,T,Z`） |

**② 数据完整性契约（`ToolResult`）**
新增 `total` / `shown` / `truncated` / `filters` / `fetched_at` 与 `integrity_line()`；
`retrieve` 透传到每条事实；`generate` **强制渲染一行"数据完整性"**，并在截断时明写
"**已截断**：以上不是全部结果，禁止使用'没有/未包含/全部'这类全集表述"。
另：`data.trains` 现在**只含下发过的明细**（不再是全集），避免下游误当全集。

**③ 表格渲染器（`generate._render_fact_text`）**
表格类工具（余票）不再走 `text[:900]`，改为**结构化投影**：
头部（区间/总数/符合条件数/过滤条件）→ **发车时段分布** → **有票席别统计** → 明细表（行数上限 `FACT_TABLE_MAX_ROWS`=40，超出显式标注"已省略 N 行"）。非表格类上限提到 `FACT_TEXT_MAX_CHARS`=4000。

**附加（同属"把没看到/失败说清楚"）**：失败工具的 `error` 原文现在也进入事实说明（此前只剩 `工具名: failed`，模型只能说"工具调用失败"，实测 F05/C06 被误述）；`ticket_query` 的**异常分支**也带上"超预售期"说明（P1-5 的 C06 走的是异常路径，此前提示丢失）。

### 验证

`test_r1_fixes.py`：
- `test_ticket_filters_do_the_set_math_in_the_tool` —— 53 趟 → 按"17:00 后 + 二等座"筛出晚间车次；无过滤时 `total=53/shown=10/truncated=true`；过滤后为空时明说"数据存在但不符合条件"
- `test_retrieve_parses_time_seat_type_from_message` —— "明晚…二等座" → `after_time=17:00, seat=second_class`；"普速" → `train_type=K,T,Z`
- `test_table_renderer_removes_900_char_cut` —— 第 8 趟之后的车次、时段分布、完整性行都能进入 prompt
- `test_failed_tool_error_is_passed_through` —— 工具 `error` 原文出现在事实说明里

### P1-6 离线车次目录覆盖不足（D04）

离线目录源自 2022 停更的 `train_list.js`，实测缺 G101 等车次，"只给车次号"这条路径直接不可用。
修复：目录未命中时，用**枢纽区间实时探测**（`HUB_PROBE_PAIRS`，默认 北京:上海 / 北京:广州 / 北京:哈尔滨 / 上海:广州，最多 4 个）
找到该车次并取回其起止站，再走正常实时查询；note 明确写"该车次不在离线目录中，起止站由枢纽区间实时探测得到"。

### P1-7 资讯缺带日期权威源（H01 / H02）

- **搜两遍**：资讯/时效类问题（开通·停运·调图·公告·最新·进展…）改为两遍检索 ——
  一遍带**时效过滤**（必应 `filters=ex1:"ez3"` 近一月，note 标注`【近一月·时效过滤】`）+ 一遍不过滤，
  两批证据都进事实块，由 prompt 的"时效优先"规则择优；百度不支持时间过滤时会如实说明。
- **禁止由推理反推时间节点**：prompt 新增规则——不得从"开通 N 周年""预计年底"倒推具体年份/日期并当事实陈述
  （R1 H02 正是由"开通 15 周年"倒推出 2011 并当结论）；无带日期来源时只能说"无法确认"。

### P2-8 低余量取数冲突（C03）

"余 1 张"这类低余量在分钟级就会变（R1 实测 G4 一等座 1 张 → 4 分钟后为无）。
修复：**仅当确有低余量（≤3）时**多查一次并比对 —— 有变化就如实写"两次采样间发生变化：G4 first_class 1→无，请以 12306 实时显示为准"；
无变化也标注"已二次校验，仍可能随时变化"；无低余量时**不额外调用**（不浪费外部请求）。

### P2-9 知识型精确数值

prompt 增加"**精确数值宁少勿错**"：编组辆数、投产/提速年份、牵引功率、车组编号若记忆不确切就不给精确值（可给区间或直接说不确定），
并点名已知易错项（AF-A/BF-A 长编组节数、大提速年份、厂商全称）。

## 6. F06-A 执行结果：按线路名查站序 + 指定径路里程（✅ 已完成）

**目标**：F06（"京沪线经过哪些站"无法回答）与 F05（问普速却给高铁口径 1320km）。

**逆向结论**（详见 [`../../datasources.md`](../../datasources.md) §1.3-b）：
同页的另一个动作 `action=desgroute` 是**三步 POST 交互**——
step1 选起始站 → 返回 `select name=r1`（该站出发线路）→ step2 选线路 → 返回 `select name=s1`
（**整条线站序**，含 `(●)` 接算站标记）→ step3 选终点 → 返回"指定径路"结果表（区间/累计里程）。

**交付**：
- 新工具 **`rail.line_stations`**（第 14 个工具）：`line=` 给站序；`line= + from/to` 给指定径路里程；
  线路别名归一（老京沪线/京沪铁路→京沪线，京沪高铁→京沪高速线）；结果**进程内缓存**（默认 1 小时）
- 路由：`rail_line` 意图在"线路名 + 问站序/里程"时走新工具；两站间"走哪条线路"仍走最短径路（**口径不混**）
- 解析加固：解析表格前剥离 `<select>…</select>`（否则 option 文本会污染单元格）

**真实数据实测**：
| 查询 | 结果 |
|---|---|
| `rail.line_stations(line=京沪线)` | **57 站**：北京 → 北京南 → 柳村所 → 北京丰台 → … → 南京 → … → 上海 |
| `rail.line_stations(line=老京沪线, from=北京, to=上海)` | **北京→上海 全程 1463 km**（客运运价里程，既有线口径） |
| 对照 `rail.line(北京→上海)`（最短径路） | 1320 km / 17 条线路 / 18 站（高铁口径） |
| 缓存 | 首次 19.4s → 命中 0.00s |

**验证**：新增 `backend/tests/test_rail_line_stations.py`（6 项，无网络）；
全量 **22 套全绿**。
