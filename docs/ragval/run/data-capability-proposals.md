## 一、F05 老京沪线里程口径（问普速，答了高铁 1320 km）

**现状**：`rail.line` 走的是黄河铁路网「旅客径路查询」的**最短径路**（客运运价里程口径），
北京→上海给的是含京沪高速线的组合径路 **1320 km**；用户问"走老京沪线（普速）多少公里"，
正确答案应在 **1463 km 一带**（既有京沪线里程）。当前回答只能诚实说明"检索结果里没有纯老京沪线里程"。

| 方案 | 做法 | 可行性 | 成本 | 风险 |
|---|---|---|---|---|
| **A. 口径声明（已在做的兜底）** 🟢 | 回答里明确区分口径："系统给出的是**最短径路（高铁口径）** X km；既有线里程不在该接口覆盖范围"，并建议用车次票面里程核对 | 现在就有 | ~0（已部分实现） | 用户仍拿不到 1463 这个数 |
| **B. 由线路名反查站序后累加里程** 🟡 | 见 F06：接入 `desgroute` 拿到"京沪线"的站序与区间里程 → 累加即得既有线里程（同一份工作同时解决 F05+F06） | 页面境内可达（本轮实测可达） | 0.5–1 天 | 依赖第三方页面结构，需抗噪解析 |
| **C. 维护"主要干线里程"小表** 🟡 | 配置/数据表：线路 → 运价里程 → 口径说明 → 来源与日期（如 京沪线 1463 km @ 官方里程表某版），回答时标注来源与"以官方为准" | 纯本地、可审计、可控 | 0.5 天（含 10–20 条干线） | 需人工维护；里程随线路改造微调 |
| **D. 车次票面里程反查** 🟡 | 用 12306 车次详情里"里程"字段（若接口返回）反推该车次经由线路的里程 | 需先确认 12306 是否在可获取字段里给出里程 | 0.5 天（探测） | 拿不到就白做 |

**建议**：**B + C 组合** —— ~~B~~ **✅ 已实施（F06-A 已完成）**：`rail.line_stations` 用 desgroute 的"指定径路"给出既有线口径里程；A 作为即时兜底保留，C 暂不需要。

## 二、F06 按线路名反查站序（"京沪线经过哪些站"）

**现状**：`rail.line` 只支持"两站之间"的径路（`action=shrtroute`）。
按线路名查站序需要该站工具的另一组动作（历史记录中标注为 `desgroute` 多步交互），未接入，路由退化为搜索兜底。

| 方案 | 做法 | 可行性 | 成本 |
|---|---|---|---|
| **A. 逆向 `desgroute` 系列动作** 🟡 | 抓 `jprailfan.com/tools/dert/index.php` 的线路选择流程（线路名 → 站序表），沿用已有的 HTTP 助手 + 电报码过滤（800KB 页面抗噪经验已具备） | 页面可达；已有同类解析经验 | 0.5–1 天 |
| **B. 离线线路-站序表** 🟡 | 一次性抓取全国主要干线（京沪/京广/京哈/陇海/沪昆…）的站序与里程，落成静态 JSON（类似现有离线车次目录），请求时本地查询 | 抓取一次即可，后续更新按需 | 0.5 天 + 定期维护 |
| **C. 保持现状 + 更明确的口径说明** 🟢 | 回答明确"该能力暂未接入，可用两站间径路替代"，并给出替代路径 | 已有 | 0 |

**建议**：**A** —— ✅ **已完成**：`action=desgroute` 三步流程已接入（step1 选站 → step2 选线路得**整条线站序** → step3 选终点得指定径路里程），见 `datasources.md` §1.3-b。

## 三、H03 京沪高铁达速状态（"现在跑 350 了吗"）

**现状**：12306 / rail.re / 黄河径路**都没有"线路允许速度/达速状态"字段**；R1 中模型只能靠检索片段 +
由"开通 15 周年"反推时间锚（已用 prompt 禁止反推，但这只是止损，不产生正确答案）。

| 方案 | 做法 | 可行性 | 成本 | 风险 |
|---|---|---|---|---|
| **A. 权威源 + 结构化抽取** 🟡 | 定向抓取国铁集团/12306 公告页与权威条目（百科"京沪高速铁路"含速度与时间线），抽取"最高运营速度 + 生效日期 + 来源" | 页面可达 | 0.5–1 天 | 百科时效性不稳定，需要多源交叉 |
| **B. "干线达速"配置表** 🟡 | 一张可审计的小表：线路 → 最高运营速度 → 生效日期 → 来源 URL → 复核日期；回答时渲染"截至 YYYY-MM-DD，据 X"，无则该说不确定 | 纯本地、可控、可审计 | 0.5 天（含 10–20 条干线） | 需定期复核（可加"复核日期"字段并在过期时提示） |
| **C. 仅靠 prompt 止损（已在做）** 🟢 | 禁止由推理反推时间节点；无带日期来源时必须说"无法确认" | 已有 | 0 | 用户拿不到确定答案 |

**建议**：**B 为主 + A 为辅** —— B 给出可审计的确定答案（含来源与复核日期），A 在表过期或缺失时补检索。
两者都要在回答里显式给出**来源与截至日期**，符合本产品"不编数据、标注时效"的一贯原则。
