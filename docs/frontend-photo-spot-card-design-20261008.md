# Main 机位卡片设计

日期：2026-10-08。状态：设计方案已接入 Main 0.1.26；新增模块初步验证，完整真机验收待完成。

依据：`backend-photo-annotation-dispute-handoff-20261008.md`、`ui-design-boundaries.md`及现有时刻、票价卡片。只调整机位展示；不修改后端、LM 或发布版本。

## 默认卡片

沿用现有助手头像右侧的结果区域，同一条回复的所有卡片共用左边界和一个头像。390dp 页面参考下保留左右页面留白及头像区域，卡片约310dp宽，不固定最低高度。

- 外框：16dp圆角、1dp现有边框色、14dp内边距、分区间距12dp。
- 标题：原文机位名称，20sp加粗；右侧低强调“机位线索”标签，不标成已认证或可导航地点。
- 已确认字段：浅色分区、12–14sp字段标签、16sp值。城市及机位类型可并排；长值换行，不压缩字号。
- 可选字段：只在 claims 有已确认值时展示对应条件分区；缺失字段不展示占位表格，不推断“不适合”。不同 group_id 的条件分别呈现，不拼成一个已确认组合。
- 争议：默认仅一个“待确认”入口，暖色辅助状态，最小44dp触控；不在卡片默认正文显示长原因、证据或数量。
- 来源：底部沿用票价卡片的“来源与查询详情”折叠行；实际来源标题和链接来自后端，长链接不铺满默认卡片。
- 操作区：复制、重新生成、分享仍由每条助手回复统一提供一次，位于卡片外。Token沿用现有位置。
- 功能图标：统一使用项目固定版本的Lucide；不新增照片、地图、导航或开放状态等后端未提供能力。

## 样例与事实边界

交互设计使用交接文档中的“笋岗桥 / 深圳 / 桥”样例。待确认说明为示意文案，运行时必须使用接口 title、note；示意稿未编造原文引述，原文依据展示的是空状态。样例不得写入生产数据。

深圳及桥可以显示为已确认字段；铁路名称未绑定实体，不显示为已确认线路，不参与已确认铁路筛选。原文名称不等于地点、坐标或通行许可已经认证。

## 待确认说明层

点击后按 issue_id 请求详情，只请求用户打开的说明。层级高于结果卡片，关闭后保留阅读位置、草稿及原回复。

说明包含标题、作用范围及 note；occurrence 与 document 分别标注“本机位”及“整篇攻略”。多个问题由同一个入口打开，说明层内逐项呈现，不新增聊天消息或头像。“查看原文依据”默认折叠，仅展示真实 evidence 及原始来源。

请求中、失败重试在说明层内处理，不将整条回复替换成连接错误。404 时刷新文档索引并提示“说明已更新”。source_status=current 仅表示原文匹配，不表示当前开放或允许进入。

## 来源状态

- reviewed：按已确认 claims 展示，存在问题仍显示待确认入口；不使用笼统的“全部已确认”。
- unreviewed：保留攻略阅读，以“尚未复核”说明来源状态；不生成已确认事实分区。
- stale：提示原文变化，旧注释不参与已确认事实或筛选。
- not_annotated / available=false：保持旧回复兼容，不能显示成没有机位，也不能自动把其他类型来源当成机位。

## 接入方式与限制

`/api/photo-spots/search` 的 items 才提供结构化机位及 claims；以 occurrence_id 与 url 关联卡片。`/documents?url=...` 仅提供来源注释索引，不能从它生成机位名称和事实字段。

可在客户端保留已有 SSE done.slots 中的明确地点参数作为结构化检索输入，不改变聊天协议，不从模型正文猜测地点和 claims。旧回复缺少可用检索范围时保留原正文及来源入口，不强行产生结构化卡片。

文档级问题放在来源范围；机位级问题绑定对应 occurrence_id。详情不预取全部问题。词典更新后失效缓存；当前接口没有独立标注修订号，第一阶段不跨会话长期缓存争议详情。

如需要仅凭 sources URL 为所有旧回复生成机位卡片，需另行与后端确认来源归属及机位字段接口；当前契约不支持，不据此补造数据。

## 实施验收要点

视觉以现有卡片的层级、留白、圆角及颜色一致为准，不要求旧设计逐像素复刻。保留真实系统安全区，不绘制系统栏或设备示意。

默认卡片只展示 eligible claims 和一个待确认入口；详情按需加载，来源/机位范围正确；关闭不丢失草稿和滚动位置；来源旧版、变更、未复核时降级正确。长标题、多条件、多问题与大字体下不截断正文、不遮挡操作。

实施通过后仍由 `scripts/acceptance.sh` 生成正式对照图和索引；本设计草稿不视为实施或验收证据。

## 2026-10-09 实施记录

原生实现为 `PhotoSpotCard.kt`；`PhotoSpotRepository.kt` 负责现有只读接口。SSE完成后按明确 location 槽位检索，保存卡片和来源索引；当前最多读取前三个聊天来源索引，结构化条目自身的争议入口不受此限制。旧历史回复保持原文，不从模型文本造卡片。网络失败保留原回答，不报成模型连接失败。

说明每次点击重新获取索引及相关说明；无跨版本持久化详情缓存。条件组不合并，坐标未新增地图或导航能力。卡片的44dp操作高度使用实际dp，不随参考画板比例缩小。

自动对照图使用冻结设计片段 `frontend/tests/visual/designs/photo-spot-card.html`；原生实测通过Compose截图采集，Edge只用于渲染设计参考，不替代原生验收。
