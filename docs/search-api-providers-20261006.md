## 三、已核实的接口事实

### P0 百度千帆 `web_search`（已接入）

```
POST https://qianfan.baidubce.com/v2/ai_search/web_search
Authorization: Bearer <API Key>
{
  "messages": [{"content": "查询词", "role": "user"}],
  "search_source": "baidu_search_v2",
  "resource_type_filter": [{"type": "web", "top_k": 20}],
  "search_filter": {"match": {"site": ["www.bilibili.com"]}}
}
```

- query **限 72 字符**（一汉字占 2），超长只取前 72 —— 这条最容易踩
- 响应 `references[]`：`url`（**真实地址，不是跳转链**）`title` `content`(≤2000) `snippet`
  `date` `website` `authority_score` `web_extensions.author_info`
- 另有 `/v2/ai_search/chat/completions` 会额外做 AI 总结 —— **建库不需要**，用 `web_search` 更省

### P0 阿里云 IQS（信息查询服务）

```
POST https://cloud-iqs.aliyuncs.com/search/unified
Authorization: Bearer <API-KEY>        # 也支持 X-API-Key
{ "query": "...", "engineType": "LiteAdvanced",
  "contents": {"mainText": true, "markdownText": false, "summary": false, "rerankScore": true},
  "advancedParams": {"numResults": 5} }

POST https://cloud-iqs.aliyuncs.com/readpage/basic      # ← 关键
{ "url": "...", "maxAge": 0 }
```

**`readpage` 是这个单子里最有价值的一条**：它直接返回网页正文，
等于把我在 `build_photo_spots.py` 里手写的 `fetch_body`（HTML→文本）换成官方接口 ——
更稳、不怕被站点 403（实测知乎 403、百度百科 403 是常态）。

开通：控制台点「免费试用」→ 自动获得免费测试额度 → 5 分钟后可用。

### P1 博查 Bocha

```
POST https://api.bochaai.com/v1/web-search
Authorization: Bearer <API-KEY>
{ "query": "...", "freshness": "oneYear", "summary": true, "count": 8 }
```

响应 `webPages.value[]`，含 `name` / `url` / `siteName` / `snippet` / `summary` / `datePublished`。
**试用 1000 次 / 3 个月**（体验包），大包有 ¥3.6/1000 次/3 月 的档位。

### P1 智谱 GLM Web Search API

- 返回结构化结果（标题/URL/摘要/网站名/图标），支持**域名过滤**、时间范围、**摘要字数可调**
- 后端整合自研引擎 + 搜狗 + 夸克
- 接入走 `zai-sdk`（`pip install zai-sdk`）
- ⚠️ **免费额度待核实**：定价页部分模型免费，但搜索 API 是否在免费范围内我没查到确证

### 腾讯云 联网搜索 API（无免费额度，但功能最全）

四档：轻量/标准/尊享/旗舰（后两档仅企业）。轻量版 ¥18/1000 次（日结）。
支持**指定网址检索**、指定时间范围、相关性得分、图片列表。

## 四、我的建议：先把「可换源」做成架构，而不是逐个硬接

现在 `qianfan_search.py` 是**单一来源**。要让"百家饭"真的可行，应该改成**多来源 + 自动轮换**：

```
app/tools/search_providers/
  base.py        # SearchProvider 协议 + 统一的 SearchResult 归一化结构
  qianfan.py     # 已实现，迁过来
  iqs.py         # 阿里云（含 readpage 正文获取）
  bocha.py       # 博查
  zhipu.py       # 智谱
  registry.py    # 按优先级排序；额度耗尽/报错自动切下一家
```

三个设计要点（都是这次踩过的）：

1. **统一归一化**：各家字段名不同（千帆 `references[].content`、博查 `webPages.value[].summary`、
   IQS `contents.mainText`），必须在 `base.py` 抹平，否则每接一家都要改建库脚本。
2. **额度记账**：本地记 `provider + 日期 → 已用次数`，接近上限自动切源 ——
   否则会在建库中途被某一家掐断（百度额度按天发放，跑一半才发现用完最难受）。
3. **正文获取分级**：有 IQS `readpage` 就用它；没有才回退自建 `fetch_body`。
   自建那条路实测会被知乎/百度百科 403，官方接口能省掉一大半失败。

## 五、额度估算：百家饭到底能跑多快

| 来源 | 日额度（估） |
|---|---|
| 百度千帆 | ≈50/天（1500 ÷ 30） |
| 阿里 IQS 试用 | 一次性试用包（够跑完整个建库） |
| 博查试用 | 1000 次 / 3 个月 ≈ 11/天，但可一次性用掉 |
| 智谱 | 待核 |
| **合计** | **≈60–70 次/天；试用包可额外一次性冲 1000+ 次** |

对比：全量种子约 **186 条查询**。
- 只靠百度：**4 天**
- 加上阿里/博查试用包：**1 天就能跑完**（一次性把试用额度用掉）

## 六、下一步（要你定）

1. **只做多来源框架**（不接新厂商）：把 `qianfan_search.py` 重构成 provider 架构 —— 纯结构改造，零新依赖，为后面接各家铺路。
2. **框架 + 接阿里 IQS**：顺带拿到 `readpage`，**把自建抓正文换成官方接口**（这条独立价值最大：自建抓取被 403 的比例很高）。
3. **框架 + 接齐 4 家**：需要你去各家注册拿 Key（阿里/博查/智谱）。Key 给我就接。
4. **先不动代码**：你只要单子，那这篇就是交付物。

我的建议是 **2**：框架 + 阿里 IQS。理由是 `readpage` 能替掉最脆的那一段（自建抓正文），
而且阿里试用包是一次性的、够把现有 186 条种子一次跑完 —— 先把库建起来，再谈换源优化。

## 七、需要你注意的三件事

   **下单前务必在控制台确认**（尤其智谱的免费范围、阿里试用包的具体次数、博查体验包条款）。
2. **智谱那条我标了"待核"**：定价页显示部分模型免费，但搜索 API 是否免费我没查到确证，
   别把它算成免费额度再决策。
3. **腾讯云无免费额度**：功能最全（指定网址/权威度/图片），但要付费，适合后续作为质量补充而不是"百家饭"主力。
