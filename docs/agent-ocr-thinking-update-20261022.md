# PaddleOCR、可续查流程与思考界面

日期：2026-10-22。基于 `docs/agent-handoff-20261021.md` 的 Main 0.1.31 快照。此次按用户要求推送源码；不递增版本、不构建 APK、不发布新 Release。

## 已实现

### OCR

Android 移除 ML Kit 中文识别，使用官方 PaddleOCR PP-OCRv5 mobile 检测、识别模型及字典，通过 ONNX Runtime 1.21.1 在设备运行。保留 8 MiB、2400 万像素、EXIF 校正和 60000 字限制；检查取消、45 秒软时限及候选区域数量。首次识别加载模型，后续复用推理会话；不需要 Play Services，不在识别时下载模型，不向 OCR 云服务上传图片。

模型约 20.5 MiB，正式 APK 增量还要考虑替换 ML Kit 和加入 ORT 的净差，尚未重新打包，不能以模型原始尺寸冒充 APK 增量。来源固定版本、SHA-256 和许可见 `backend/resources/ocr/paddle/manifest.json`；模型为 Apache-2.0，ORT 为 MIT。最低 Android SDK 保持 24。Main 打包模型及推理依赖；LM 不增加模型或运行库。

Android 后处理采用轻量连通区域及轴对齐裁切，支持多行排序和高窄区域旋转；不是完整 OpenCV 多边形透视管线，严重倾斜、弯曲文字的识别效果待实际图片评估。模型形状和字典已静态核对；不能据此宣称识别准确率提升。

桌面后端改为隔离子进程中的 RapidOCR + 同一套官方模型，30 秒硬超时。依赖单独在 `backend/requirements-ocr.txt`，不进入 Android Python 依赖。本机已经安装该可选依赖；其他部署需安装后再启用本地 OCR。缺模型时失败，不自动联网下载。图片输入开关仍决定直接给视觉模型看图还是走本地文字识别，隐私语义不变。

### 可续查的模型流程

首次检索仍复用既有决策、检索层；不改变其日期、区间及数据源边界。若失败、空结果、部分结果，或属于需要分析的机位、资料等问题，进入 `pipeline/agent_loop.py`。该流程让模型观察已取得的事实、失败原因及历史，选择下一项查询；每轮拿到新结果后重新决策，最多四轮补查，再生成最终分析。

例如机位库没有 6420 的资料时，模型可以补查 6420 的查询日时刻，再说明可确认的时刻和仍缺少的机位信息。时刻表不能当作保证实际开行的证据，无记录也不能判停运。

使用通用 JSON 调度协议，不要求服务商支持原生函数调用。模型可选择时刻、动车交路、票价/余票、机位、站点、线路和公开资料检索；仍经过现有只读检索层，不开放任意代码、任意 URL 或写操作。每轮规划最多请求 768 输出 token、超时 45 秒；每轮补查超时 45 秒。识别相同意图及槽位的重复请求后停止。所有模型用量计入本次回复，沿用会话隔离。

原始未来日期固定带入补查，不能通过省略日期改查今天的交路。未来交路不查询；普速交路支持范围、实际乘车区间和数据新鲜度限制继续由检索层执行。失败及空结果卡片保留，模型可以补充分析，不再把所有失败后的正文一律收回。原检索卡片不会因补查规划异常被丢弃，取消继续传播到上游任务。

简单且已成功的时刻/票价等结果维持直接交付，不为显示卡片强行再调模型。未配置模型、模型服务故障时不能承诺完成补充分析，已有查询结果仍保留。Mock 及 LM 不进入新补查循环。

### 思考开关

输入框下方左侧新增“思考”滑块，默认关闭，发送请求字段 `thinking_enabled`。旧客户端不传字段时保持原有默认策略；显式关闭时客户端不会接收公开的思考字段。开启时按服务商方言请求可用的思考输出；服务商拒绝可选参数时仍沿用参数兼容降级，不伪造思考、不承诺所有模型支持。

助手回复内提供可折叠思考区，生成中也能折叠。思考与正文分开，逐条保存在对应会话消息中；停止、失败和重新打开会话时保留已收到内容，迟到事件受到请求标识检查。思考不会作为普通历史对话重新发送，也不自动进入个人记忆。

设置页新增“默认折叠思考内容”，默认开启，普通保存及向导保存都持久化。流式过程先展示思考，完成后按该设置默认折叠。该偏好控制显示，不控制模型是否执行思考；输入区开关才控制本次请求。

### 手势与上抬

主页整页可向右滑打开侧栏，包括从按钮内起手。方向判断在子按钮处理前进行；明确右滑后取消按钮点击，40dp 触发，明显竖向或多指不接管。用户本次要求提高侧滑优先级，因此主页右滑优先于表格的同方向横拖，左向拖动仍交内容处理。

消息区原有距底部不超过 32dp 的跟随逻辑保留。贴底状态下键盘、附件面板或输入框尺寸变化触发上抬时，会滚到最新内容底部；离底阅读时保持阅读位置。思考增量也纳入跟随及新内容状态。
