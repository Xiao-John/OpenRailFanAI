# Main 客户端交叉评测结论（2026-10-03）

## 两次评测的独立性

主评测的审美报告先写入文件，再读取 GPT-6.1 Sol 的盲测报告。双方没有提前交换发现；分别使用不同模拟器，无并发操作争抢。主评测使用全新数据、390×844、密度160，并有自动截图；盲测使用现有安装、1080×2400、420dpi，主要依据真实操作、可访问文字和节点边界，未生成截图。因此盲测不支持色彩、图标质感等纯视觉结论，主评测也不能代替盲测验证过的长内容交互。

独立报告：`docs/main-aesthetic-review-20261003.md`、`docs/blind-ergonomics-review-20261003.md`。本轮只做评测和自动采集工具，不实施产品修复。

## 对照结果

| 问题或优点 | 主评测 | 盲测 | 综合判断 |
| --- | --- | --- | --- |
| 错误归因为密钥无效 | 本机地址连接失败后仍显示密钥无效 | 未配置与本机地址被拒绝都复现同一结论 | 双方独立确认；客户端默认错误呈现与实际原因不一致，需按错误类别恢复。 |
| 空对话占位符 | “继续追问…”不符合首次提问 | 独立指出同样歧义 | 双方独立确认；按空对话和已有对话区分。 |
| 设置流程 | 对齐改善，但按钮过重、表单很长 | 配置理解成本高，测试与保存均可操作 | 功能进步已有证据；下一轮应减少辅助操作的视觉重量，明确当前配置状态。 |
| 提供商选择 | 390px视口底部项需滚动，自定义不易发现 | 选中OpenAI完成流程，未发现切换阻断 | 不冲突：首屏能选择部分选项不等于所有选项易发现；作为可发现性改进，不称功能失效。 |
| 时刻卡片 | 车次、方向、线路轴层级清楚；细字偏淡 | 七站表易扫读，来源、口径可查 | 保留当前卡片结构，改善细字与图标；无需全面重画。 |
| 键盘与单一输入区 | 未见双输入框或系统遮挡 | 实际输入发送可用，边界随键盘上移 | 两个环境中均有基础可用性证据，不推广到所有设备。 |
| 历史抽屉 | 结构清楚；单条会话标题、副标题重复 | 搜索、改名、取消删除正常 | 保留抽屉导航；精简摘要；草稿保护另列优先问题。 |
| 重开会话丢草稿 | 未覆盖 | 同一会话重开重复复现 | 接受为盲测独立发现，不能因主评测新建成功而否定。 |
| 回到底部 | 仅评视觉固定状态，未实时验证 | 点击后消失；普通回看也显示“有新内容” | 行为已改善；文案应区分离底与实际新增内容。 |
| 换日期 | 未实际点击 | 得到“其他日期”的含糊草稿 | 有待明确日期输入入口；不是已证实查询到错误日期。 |
| 降级回复范围 | 无效配置流程仅观测错误 | 复合需求只返回票价，技术信息过多 | 结果组织和完整性应单独评审；涉及后端与展示边界，不作为单纯审美修复下达。 |

## 建议的处理顺序

1. 先保护草稿并校正错误提示。两项直接影响信任和用户已输入的内容，优先于装饰性改动。
2. 在一次集中设计修改中精简设置表单和提供商弹层：保留主操作，降低粘贴、获取模型、高级设置的视觉重量，改善滚动列表的提示。
3. 统一列车图标资源与辅助文字，修正空对话占位符、重复历史摘要、无新增内容时的回到底部文案；保留已清楚的时刻及交路卡片结构。

日期入口与降级结果范围需要产品和数据语义复核后独立处理。本报告不授权改变后端协议或已有时刻口径。

## 下一轮复查

使用同一组真实用户流程复查，不仅查看固定状态：配置并保存、查询失败恢复、编辑长草稿后开关历史并重开当前会话、长卡片滚动、换日期。另补深色主题和系统大字体。真实模型成功路径未测，应使用明确授权的有效配置另行记录，不能用本轮虚构密钥的失败路径替代。
