# Main 原生界面：整体协调优先验收

## 用户授权

2026-10-03，用户明确要求：放宽尚未完成验收的标准，先保证整体和谐，不再追求足够接近设计稿。本规则覆盖旧的未完成像素验收门槛；已有通过证据和历史运行记录保持原样。

## 新的视觉验收

逐一检查时刻、交路、查询中、部分成功、无记录、连接失败、阅读追问、查询详情及历史九种状态：

- 保留原稿的蓝色主操作、浅色卡片、清晰标题和分层信息；同级控件采用一致的字体、圆角及留白。
- 文字在390px界面中可读，数据列清晰，不发生意外换行、截断、挤压或叠压。
- 操作入口易识别，与所属内容相邻；图标形状可辨认、风格协调，不为消除微小轮廓差反复调整。
- 小幅位置、尺寸、字体与图标轮廓差异可接受。旧的2px布局及1px图标结果继续保留为诊断，不单独决定未完成项目是否通过。
- 组件独立示意与实际页面上下文不同的地方按实际页面检查，不要求补造画框、墨迹并集或另一种时刻表布局。

## 保持严格的要求

- 关键触控区域至少44dp；回到底部、复制、建议操作和固定输入区不互相遮挡。
- 输入区适配真实系统安全区与键盘，不模拟设备状态栏，不重复增加系统边距。
- 停止、失败项重试、日期切换、最近记录、错误恢复、追问草稿、复制和历史管理有实际操作证据。
- 不改变时刻口径、来源和日期语义，不将无记录推断为停运，不泄露密钥。
- 缺截图、缺真实运行、操作失败或关键内容不可见仍不得通过。后端查询跳过项明确记录，不称为端到端成功。

## 证据与记录

- 正式截图、设计对照及索引仍由 `./scripts/acceptance.sh --main-compose` 自动生成，禁止以手工截图替代。
- 原图参考保持不变；比较图保留原始模块与390px实际截图，禁止靠缩放或裁切掩盖差异。
- 整体协调评审绑定实际截图哈希，逐状态说明检查结论；缺评审或截图哈希不一致时保持未验收。
- 严格像素结果与新标准的最终结论分开记录；不能把原有failed或unmeasured改称为原门槛passed。
- 完成界面验收后还需核对Main原生入口、配置迁移和实际启动路径，不能用测试夹具通过代替产品可用。
