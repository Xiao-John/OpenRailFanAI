# 票价卡片前后端交接

日期：2026-10-05。范围：Main Android；后端正在进行的修改保持独立。

## 当前客户端实现

客户端新增 `FareCard.kt`，由 `MarkdownAnswer.kt` 接入，复用现有色彩、16dp圆角、边框、字体层级和回复内容区域。

- 识别现有明确的票价回执：区间与日期标题、车次/区间/到发时间/历时行、完整席别金额列表；逐行保留其他说明。
- Markdown 的“席别／票价”两列表格使用票价卡片容器，周围正文仍保留。
- 不从用户提问或时刻卡片推测票价、日期或乘车区间，不计算金额，不推断余票。
- 格式无法完整识别时保留原始 Markdown；缺少票价不伪造成功卡片。
- 复制、分享及会话存储继续使用原始回复，客户端仅改变呈现方式。

本轮不修改 `backend/`、外部接口、SSE字段、展示协议、后端服务或版本。无需后端立即配合即可使用当前格式；已生成的0.1.17安装包不包含这次源码修改。按用户停止调试的要求，仅做编译检查，不宣称完成原生运行或视觉验收。

## 建议后续协作：稳定的结构化票价结果

正文识别是兼容方案，不能覆盖后端未来所有文案形式。需要稳定支持多车次、多区间、部分失败和来源详情时，建议安排前后端同步任务增加结构化票价结果。以下为候选契约，**尚未实施，不要求当前后端任务立即改动**。

每个独立票价结果至少携带：

| 字段 | 含义 |
| --- | --- |
| `kind` | 候选值 `ticket_fare`，须与客户端同步确认后添加 |
| `schema_version`、`status` | 沿用版本及成功、空结果、失败的明确语义 |
| `train_code`、`date` | 实际查询车次和乘车日期 |
| `from_station`、`to_station` | 每条实际票价对应的乘车区间，不以邻站或列车全程替换 |
| `start_time`、`arrive_time`、`duration` | 上游返回的区间时刻，可缺省；不标为实时运行状态 |
| `prices` | 每个席别的原始名称、金额及明确币种；缺失值不能当作0元 |
| `sources`、`fetched_at` | 真实来源及采样时刻；不可由客户端虚构 |
| `error`、`note` | 无精确记录、查询失败、数据限制及票价不代表余票的说明 |

多车次查询逐项保留归属和失败状态；每条结果可独立展示，不以某个车次的成功覆盖另一车次的缺失。一个车次返回多个实际区间时逐条保留，不能合成一个没有实际来源的票价。

兼容交付时继续保留可读正文，旧客户端忽略未知结果种类后仍能阅读。新客户端收到结构化票价后才抑制对应的重复正文，不能提前删除现有票价文本。未知字段、未知版本及无法确认的结果均有正文降级路径。

## 后端负责范围与完成条件

后端负责人可在后续同步任务中确定工具数据到展示对象的投影；不得顺带修改Android UI、会话Token、版本、签名或正式验收文件。涉及外部契约变化，先确认上述候选字段与客户端解析方案，再实施。

完成条件是：同次真实响应的车次、日期、实际区间、各席别金额和来源能逐项对应；部分失败不丢失成功结果；票价与余票保持独立口径；旧客户端仍能读到结果。当前文档不构成已经通过这些验证的证据。
