# Main 客户端独立视觉与操作评测（2026-10-03）

## 范围与方法

本报告在读取另一名评测者的结论前独立完成，重点评价视觉质量，并按首次使用流程观察操作。对象为已安装的 0.1.10 发布 APK。使用独立、全新数据的 Android 35 模拟器，390×844、密度160；系统状态栏、导航栏和键盘属于系统，不作为应用绘制缺陷。

实际流程：首次打开 → 设置 → 打开提供商选择 → 滚动找到自定义提供商 → 填地址、密钥、模型 → 测试连接失败 → 保存返回聊天 → 点击时刻示例并编辑草稿 → 发送并观察错误 → 打开历史侧栏 → 点击遮罩关闭 → 新建空对话。使用无效的本地地址与虚构密钥，没有发起付费云端模型调用。成功查询的视觉评价来自既有自动采集的固定状态，不能证明真实查询链路或返回底部交互成功。

截图均由 `./scripts/acceptance.sh --ergonomics-walkthrough` 自动生成；流程证据位于 `acceptance/ergonomics/20261003T222418/index.yaml`。首次尝试在自定义提供商尚未滚入视口时停止，保留在 `acceptance/ergonomics/20261003T222158/index.yaml`，随后明确加入滚动动作完成流程。这是可发现性证据，不是功能不能使用的结论。观察记录不替代正式验收。

## 总体判断

聊天结果卡片已形成清晰、统一的蓝白视觉风格，时刻线路轴和交路列表有辨识度；设置页仍明显偏向表单堆叠。主要问题是辅助按钮过多、信息密度与层级不均衡，以及细字和图标质量不足。整体属于“基本整洁，但尚未精炼”，需要集中优化设置流程与细节，暂不需要再迁移技术栈或全面推翻聊天布局。

## 视觉改进优先级

### 优先级一：设置页的视觉层级与长度

证据：`04-settings-filled.png`、`06-connection-failed.png`。输入字段需要保持统一，但粘贴、获取模型、高级设置不应都占用完整大按钮。主要动作保留测试连接与保存，辅助动作降低视觉重量。提供商名称在滚动填写时应易于确认。这能同时减少页面长度和寻找操作的成本。

### 优先级二：提供商选择的可发现性

证据：`03-provider-picker.png`、`03b-provider-picker-scrolled.png`。目前独立弹层已经解决反复点击切换选项的问题；剩余问题是列表过长、每项框线过重、底部选项露出不完整。需要保证用户能看出还有内容，并方便找到自定义项，而非通过多轮盲点选。

### 优先级三：图标与细字的一致性

证据：`01-home.png` 与既有时刻、交路截图。列车标志像低分辨率位图，其他线性图标较锐利，质感不统一。来源、固定时刻说明、停留时间和历史副标题尺寸偏小、颜色偏淡；业务时刻主体清楚，但重要解释不应过度退到背景。建议统一图标资源和辅助文字尺度，保留当前卡片布局。

## 应保留的部分

- 时刻卡片的车次、起终点、日期与线路轴层级清楚，适合快速浏览。
- 交路卡片将记录时间与时刻查询入口分开，语义比纯文字回答清楚。
- 键盘出现后输入区仍在可操作位置，未观察到双输入框。
- 历史抽屉保留当前聊天上下文，搜索、新建、分组的结构合理。
- 错误恢复按钮可见，浅红反馈比隐藏日志更容易理解。

## 尚未覆盖

深色主题、大字体、其他Android版本、横屏、真实成功的模型请求、真实长回答的回到底部以及多会话重命名删除未在本次独立实时流程中验证。既有固定截图仅供视觉补充。本报告不对这些项目给出通过结论。
