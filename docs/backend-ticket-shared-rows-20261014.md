# 票价与余票共享取数交接

日期：2026-10-14。实现已完成，未发布 release，未替换正在运行的后端。前端协议不变，无需客户端配套修改。

## 行为变化

Main 的单次检索中，同日期、同方向区间、同乘客用途及同配置的车次，共享完整售票原始记录。余票从该记录解析，票价仍根据每个车次的内部编号、乘车区间站序和席别代码，独立查询实际执行金额。返回邻站的记录不会被改名为用户请求的站。

共享发生在筛选车次、席别和时段之前；即使批量任务因并发上限分批执行，后面的车次也能复用已经完成的区间记录。原始记录按请求保留，最多 128 个键，结束后释放，不新增跨请求原始记录缓存。已有最终余票 15 秒、时刻表 30 秒快照和工具在途合并保持原规则。

本轮共享范围从检索执行开始。此前在云端决策期间已经启动的投机预取仍按既有工具结果复用规则处理，尚未与这份原始记录合并；同车不同号增强路径的独立 raw rows 抓取也未迁入本模块。这些属于后续可继续减少取数的路径，本轮直接服务测量没有启动预取。

余票低余量校验使用独立刷新标识，强制重新取数。它不复用原始快照，也不与普通查询的在途任务误合并；余票初次采样时间会保留在结果中。公布票价仍从本地词典读取。

新路径使用现有执行票价抓取客户端及其 Cookie、TLS、代理与连接复用策略；初始化不跳过，网络异常保留最多三次尝试，每次重新访问 init。业务/响应格式错误不自动重试，不把失败存成成功。未进入请求共享范围的调用继续走原路径；LM 不启用本功能。

## 取消与隔离

键包含完整配置摘要、规范日期、起终站电报码、乘客用途及刷新标识，原始结果返回深拷贝。日期、方向、用途或配置不同的查询不能共享。

取消一个等待者不会取消其他等待者需要的工具。工具在途合并可能由第一位调用者启动、由另一位继续等待，因此共享范围会在该工具工厂仍有合法等待者时保留，最后一个工厂释放后清空。整个请求取消且无其他等待者时，会取消并回收上游任务，不留下无条件后台工作。

## 结果验证

新增 12 项专项测试，与相关票价、余票、日期、交付及批量套件合计 **144 项通过**。专项覆盖：

- 十车联查跨并发批次复用；同日期一次 init、一次列表、十次执行票价，全部二十项服务取得受控结果，共 12 次 HTTP 操作。
- 多日期各自取数、区间/乘客用途/配置/请求隔离、可变结果隔离。
- 低余量重新采样、单车票价失败保留同车余票、失败后可重查。
- 部分等待者取消、整个请求取消、第一请求取消而另一请求仍等待同一工具。
- 网络重试、关闭开关、LM 原路径、邻站数据不冒充请求区间。

另通过既有 RT 性能 9 项、后端性能 11 组、流水线性能 9 组回归。专项已加入 `backend/tests/run_all.sh`；本轮没有运行全项目验收。

## 真实接口对照

独立进程、相同输入、明天（2026-10-15），交替关闭/开启共享，每种模式每个场景各 3 次，共 12 请求。每条开始前清空本进程工具结果缓存和在途表，抓取客户端可继续复用；禁止云端模型生成，所有请求 0 token。未启动或替换其他服务。

| 场景 | 关闭共享：检索中位数 | 开启共享：检索中位数 | 观测降幅 | 结果边界 |
| --- | ---: | ---: | ---: | --- |
| G1 北京南→上海虹桥票价＋余票 | 383.5 ms | 292.9 ms | 23.6% | 两侧每次均取得票价、余票记录 |
| G1、G3 同区间票价＋余票 | 349.9 ms | 297.6 ms | 14.9% | 两侧每次 G3 均无票价记录、余票失败；部分失败场景 |

单车每次的实际 HTTP 操作由 5 次降为 3 次：两路独立 init/list＋执行票价，变为共享 init/list＋执行票价。两车样本由 7 次降为 3 次；G3 无匹配记录，因此没有额外执行票价请求。计数排除了 MCP 父操作，未重复计算 init/query。

这些是小样本观测，仍包含上游网络波动与客户端连接状态差异，不能将 23.6% 或 14.9% 视为稳定承诺。第二行不是完整成功的两车性能基线；十车完整成功仅用受控传输验证。本轮未证明全系统平均耗时改善超过 30%。

另一次初步真实检查确认了时刻查询、单车联查和两车部分失败均正常交付；其耗时只作为初步观测，正式对照以本节交替测量为准。

## 修改与运维

新增 `backend/app/tools/ticket_snapshot.py`。检索及批量执行入口建立共享范围；`_rt12306`、`executed_fare`、`ticket_query` 接入原始记录或采样时间；registry 工具工厂保留共享范围的生命周期。未修改聊天/SSE、展示结构、前端或版本。

默认启用。需要回退时，在后端环境中设置 `MAIN_TICKET_SHARED_ROWS_ENABLED=false` 并重启对应后端；这只恢复原先取数路径。LM 自动禁用。该开关属于后端环境变量，无需前端设置项。

新增脱敏缓存计数 `caches["rt.sale_snapshot"]`（hit/miss/joined 等）及 `io.rt.sale.init` / `io.rt.sale.rows` 操作耗时。它们与 `fare.execution` 分开记录；不保存输入、响应正文或密钥。

证据目录：`.ai/ticket-shared-rows/20261014-v1/`。`comparison-samples.json` 是逐请求工具状态、非空记录数、操作数及耗时；`comparison-summary.json` 是汇总；`tests.log` 是 144 项回归结果。`compare.py` 可重跑真实对照，`measure.py` 保存初步诊断。沿用审计脚本的混合指标文件包含离线探针，不应用作真实请求成功率的分母。
