# Main 文案审查修订（2026-10-06）

## 客户端已修订

- Android 与 WebUI 错误标题区分配置、认证、网络和服务异常；未知异常不再称为模型连接失败。WebUI 不再仅因提及 API Key 就断言密钥无效。
- Android 设置页按返回错误显示恢复建议；未知错误不要求更换密钥。未收到具体原因时显示请求未成功，不推断错误来源。
- 余票列明确标为查询时状态；有票、无票是快照结论。票价仍可作为购票参考，余票不保证抢票成功。
- 票价查询区间时刻与票价口径明确命名；卡片说明合并为一个区域并去除完全相同的句子，保留来源返回的事实限制。
- 图定时刻说明明确计划性质；词典更新默认文案减少 GTFS、提交等技术术语。

## 后端文案交接

以下仅为建议，本轮未修改后端逻辑或输出协议：

1. `backend/app/pipeline/ticket_answer.py` 的余票结尾建议统一为：余票为查询时快照，不能保证购票时仍然有票；请以 12306 购票页面显示为准。
2. `backend/app/tools/ticket_price.py` 的公布票价失败分支同时使用“接口暂不可用”并不准确，因为公布价来自本地词典。按实际来源说明“未取得公布参考票价”或“票价数据源暂不可用”。
3. `backend/app/tools/ticket_query.py` 及 `pipeline/generate.py` 中“有票席别统计”建议明确为“查询时有票的车次数量”；保留原始张数，不把快照说成未来保证。
4. 票价工具备注与 `fare_result.py` 通用说明都包含“可作为购票参考”，建议后端集中输出一次。客户端仅能去除完全相同句子，不能可靠消除语义重复。
5. 认证、模型不存在、地址拒绝、铁路工具失败等错误应保持明确来源，方便客户端给出准确恢复建议。未确定来源的异常保持通用服务异常。

历史测试报告与旧交接文档保留当时记录，不批量改写。产品文案适用当前客户端修订；后端新输出与本说明对齐。
