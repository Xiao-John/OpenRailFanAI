# 图片、文档入口与车次兼容按钮接入

日期：2026-10-19。版本：Main 0.1.29。

## 图片与文档

输入栏增加 44dp 导入按钮，弹层提供“导入图片”和“导入文档”。继续使用系统文件选择器，单份上限 8 MiB。选好后显示文件名、大小及“发送后处理”，可移除，未发送草稿保留。重新导入成功后才替换已有附件，取消选择不移除原件。

附件按会话保存在内存，不将字节写入聊天 JSON。切换会话不会把附件带到另一会话；处理成功释放，失败保留。文本导入命令仍使用相同选择器入口。导入时保留已有问题；空白或导入命令草稿才替换为默认的可编辑问题。

复用交接实现中的图片能力声明与本地 OCR 分流、文档正文提取、一次能力回退和附件重新生成保护，不新增后端协议。文档入口列出支持类型，不宣称支持 PDF 或 Excel 二进制。

## 一键FUCK_CR

Main 设置页新增“车次规则兼容”卡片。进入设置或设备内后端地址变化后读取 `/api/fuck-cr/status`，可手动刷新。只有后端返回支持的协议、真实布尔值、规则已就绪且允许开启时，才允许发送启用请求。

当前规则未就绪时显示“适配准备中”，按钮禁用；shadow 不标为启用。404 显示服务不支持。409 读取服务返回状态，不自动重试；网络异常保留上次确认状态，不乐观宣称启用成功。未加入本地规则开关、环境文件写入或后端重启行为。

讽刺文案仅位于此设置卡片：

- 简短引语：“字母升官，代码加班。”
- 点击“这是什么？”展开：“开关已经到岗，兼容规则还在赶末班车。”
- 补充说明：“发布日期不是开关，表达对改革的热情也不能代替适配。”

说明同时明确新版未就绪时仍按现行规则查询。正常查询结果、错误和数据事实保持正常产品口径。没有给 LM 增加入口。
