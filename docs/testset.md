# RailFanAI 车迷测试集（v1）

> **一句话**：把一个普通车迷日常会问的问题，整理成 **96 条**（≤100，符合规模要求）"考题"，逐条拿去问
> RailFanAI，看它**答得准不准、老不老实、好不好用**。
> 本文档以**不懂技术的车迷视角**编写：全程不碰代码，只打开对话页面"打字 → 看回复 → 对答案"。

## 0. 这份文档怎么用（3 分钟读完）

1. 找会弄电脑的朋友把服务开起来（怎么开见 `docs/run.md`；**测试模式**要求见第 1 节）；
2. 先读第 2 节「格式声明」——看懂每条考题的五个栏位和判定口径；
3. 从 **★核心条目**（共 10 条）开始测，普通条目按第 2.4 节的建议抽测；
4. 测完把结果登记到第 5 节「测试记录表」；发现问题按第 6 节模板反馈。

## 1. 测试准备（开测前确认）

### 1.1 两种运行模式

| 模式 | 怎么开 | 能测什么 | 不能测什么 |
|---|---|---|---|
| **真实模式**（连线问答） | 配好"钥匙"（`docs/run.md` 有人会弄就行），人在**能正常打开 12306 的网络**里 | 本测试集**全部条目**（A/C/D/E/F/G/H/I/K/L 类的数据必须靠它核对） | —— |
| **演示模式**（无钥匙开机） | 开机脚本默认模式 | J 类界面操作、空输入是否崩溃这类"流程通不通"的条目 | **一切涉及"回答内容是否靠谱"的条目（演示模式下的回答内容不作数）** |

> ⚠️ **凡是期待结果里带"与 12306 一致 / 车迷群核对"的条目，一律在真实模式下测**；演示模式只看流程和界面。

### 1.2 手边的对照物（当"标准答案"用）

- **12306 App**：余票、时刻、经停站、预售期，以它为唯一权威；
- **车迷群 / 交路号查询渠道**（群友、公众号等）：担当车组（交路）类问题的核对渠道；
- **客里表 / 线路资料**（车迷圈通行资料）：里程、径路口径的核对渠道；
- 一支笔：随时记下**提问时刻**（几点几分问的），实时数据全看这一刻。

### 1.3 全局测试规则

1. **每条考题独立**：除备注标了【接上轮】，其余每条开测前先点「新对话」；
2. **装傻到底**：不要提示它任何答案，就当一个啥都不知道的车迷；
3. **实时类集中在同一时段测**，提问时刻相差别超过 1 分钟，方便和 12306 对表；
4. 测试中断网、关网测完记得**把网插回来**（K04 有专门说明）。

## 2. 格式声明（先读这个，再看用例）

### 2.1 每条用例的五个栏位

| 栏位 | 含义 |
|---|---|
| **编号** | 大写字母 = 分类，两位数字 = 序号（A03 = 交路类第 3 条）。编号后带 **★** = **核心必测**条目。 |
| **我要问的话 / 要做的事** | 「」里的原话**整句复制**进对话框；标了 **（操作）** 的条目不用打字，是界面上动手。 |
| **我期待的结果** | 大白话：一个合格的车迷向导"应该"怎么答这一句。 |
| **怎么算通过** | 可核对的硬条件：去 12306 对照、去车迷群问、或界面上直接看得见的现象。列出的条件**全部满足**才记「通过」。 |
| **备注** | 特殊前提：需要真实模式 / 需要先问上一句【接上轮】/ 测完要恢复现场 等。 |

### 2.2 结果判定口径（三档）

| 档 | 定义 |
|---|---|
| **通过** | 「怎么算通过」的条件全部落实。 |
| **部分通过** | 主体达成，但有明显小毛病（**不计入通过率**，但现象必须写进问题清单）。 |
| **不通过** | 出现下列**一票否决**情形之一：① 编造数据（车次/车组/站名/时刻/里程/票数）；② 给出危险或违法的建议；③ 答非所问还硬答；④ 程序报错、无响应或界面崩坏。 |

### 2.3 优先级与执行建议

- **★核心条目共 10 条**：每次测试**全量必测**（改版前后各测一轮，用于对比回归）；
- 普通条目每次**抽测约三分之一**，并在测试记录表里注明本轮抽了哪些编号；
- A 类（担当车组）是本产品的招牌能力，除 ★3 条外，其余 9 条建议每轮至少抽测 3 条。

### 2.4 车迷速查词表（避免歧义，写给帮忙测试的朋友）

| 词 | 意思 |
|---|---|
| 交路 / 担当 | 哪组车跑哪趟车（"G1 今天由哪组车担当"） |
| 车底 / 车组 | 一组固定的车（形如 CR400BF-5054），"车组号"是它的官方编号 |
| 车次 | G/D/C/K/T/Z + 数字（G1、1461……），12306 上查得到 |
| 电报码 | 车站的三字母短码（北京南 = VNP、北京 = BJP，12306 口径） |
| 径路 / 客里口径 | 两站之间走的线路；里程按"客运运价里程"算，跟公路里程不是一回事 |
| 机位 | 拍车的位置 |
| 候补 | 12306 排队等退票的机制，显示"候补"≠"有票" |
| 预售期 | 车票提前发售的天数（现行为 15 天，以 12306 当时公告为准） |
| 达速 | 按最高运营时速跑（如京沪高铁 350） |

## 3. 用例正文（96 条 / 12 类）

### A. 交路与担当车组（12 条，★3）—— 招牌能力，全部真实模式

| 编号 | 我要问的话 / 要做的事 | 我期待的结果 | 怎么算通过 | 备注 |
|---|---|---|---|---|
| A01★ | 「G1 今天由哪组动车组担当？」 | 报出**带横杠的车组号**（形如 CR400BF-5054），注明"今天（×月×日）"，并给出数据出处 | ① 车组号发车迷群核对，与当日交路一致；② 回答里明示了日期；③ 车组号格式规范（不吐一串无分隔的字母数字）；④ 附来源 | —— |
| A02★ | 「G1 昨天是哪组车？」 | 给出昨日的车组（或明确标注"最近一条记录是哪天的"），日期能对上 | 群内核对昨日交路一致；或如实说明"昨天没有记录，最近一条是×日"；**不得编** | 交路数据是"记录到哪天算哪天"，允许它说明局限 |
| A03★ | 「CR400BF-5054 今天都跑哪些车次？」 | 列出该车组当日车次（可能好几趟连跑，G/D 都有），标注"今日" | 与当日交路核对一致；列出的每个车次在 12306 上真实查得到 | 用 A01 答案里的那个车组号来问最好 |
| A04 | 「CR400AF 今天的车都担当了哪些车次？」（按车型问） | 给当日该车型担当的车次，说明覆盖范围 | 抽查 1–2 趟反查"这趟今天用啥车"，能对上同一车型 | —— |
| A05 | 「g1次列车今天的车底是啥？」（故意小写＋"次列车"） | 照样认出 G1，回答口径同 A01 | 结果与 A01 一致；没有因写法怪而生搬错车 | 考"车迷口语宽容度" |
| A06 | 「CR400BFA5054 昨天跑了什么车？」（写成没横杠的） | 不因少个横杠认错对象，按车组反查 | 结果与 A03 同口径（昨天版）；群内核对 | —— |
| A07 | 「（任挑一趟动卧，如 D311）今天由哪组车担当？」 | 有据就报车组＋来源；查不到就明说"这趟的担当数据没查到" | 不编车组号；动卧/冷门数据不全时**老实交代** | 考"查不到时说不查不到" |
| A08 | 「G1 明天由哪组车担当？」 | 明说"明天的还没出来/数据支撑不了"，或给最近记录并说明局限 | **绝不拍一个明天的车组号**；解释合情理 | 交路是已发生的记录，未来没有——考它会不会装先知 |
| A09 | 「京沪标杆今天用什么车？」（黑话指代） | 能对上具体车次（G1/G2 一类），或友好追问"你指哪一趟标杆" | 给出的车次确实属京沪通道当日交路；或追问而不是瞎猜 | 考黑话理解 |
| A10 | 「上个月15号 G1 是哪组担当的？」 | 给那个日期的记录（带日期标注），查不到就明说 | "上个月15号"换算成的日期**算对**；记录口径与车迷渠道一致或如实缺数据 | 考历史日期换算 |
| A11 | 「CRH380B 今天跑哪些车次？」（老车型） | 有据给列表；覆盖不到就说明 | 抽查反查一致；或如实说明；**不编列表** | —— |
| A12 | 「G1 的担当车组今天还跑别的车次吗？」 | 给该车组当日其余车次（即"整日交路"），可续读 A03 的对象 | 与 A03 的结果互相印证（同一个车组号）；日期能对上 | 考"连跑"信息的完整性 |
